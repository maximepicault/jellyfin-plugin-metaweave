# Genres and tags rules

> Detail moved out of `CLAUDE.md` to keep the always-loaded file small. Read it when touching `TaxonomyStore`, `TaxonomyService`, the taxonomy page. `CLAUDE.md` still holds the rules that apply everywhere.

**Genres and tags rules (page `CustomMetadataTaxonomy`, 5th tab of the shared bar).** `Services/TaxonomyStore` (`DataFolderPath/taxonomy.json`, plus `taxonomy-seen.json` = terms received at import, written 15 s after the last change): rules `{Kind genre|tag, Name, Ignored, ReplaceWith, Created}` matched on `Key(name)` (lower case, no accents, single spaces; punctuation kept: `Sci-Fi` ≠ `SciFi`). `ReplaceWith` with the SAME key = a spelling fix (ends the chain); a chain A→B→C is followed (10 steps) and a cycle is broken at save; "ignore" wins over "replace"; a rule that does nothing and was not `Created` is dropped. Applied through the static `TaxonomyStore.Genres/Tags(...)` (the instance is `TaxonomyStore.Current`, built at startup because it is also an `IHostedService`) at EVERY import point: `CustomEpisodeProvider`, `CustomSeriesProvider`, `CustomSeasonProvider` (after the series name is added as a tag: the rules come last), `MissingEpisodeService.AddOverviewItems`. **Jellyfin MERGES the tags of a refreshed item with the existing ones** (observed: `tech` stayed next to `Technologie`), so `Services/TaxonomyService` (also a hosted service) listens to `ItemUpdated/ItemAdded` and rewrites a MANAGED series/season/episode (a tag of a configured source in its path, or the `custom` id) whose terms a rule changes; idempotent (once right, `Change` is false, which ends the event the rewrite raises). `POST CustomMetadata/Taxonomy/Apply` does the same for the items already there (background, static lock, `GET …/Apply/Status`; `GET …/Impact` counts first). `GET/PUT CustomMetadata/Taxonomy` = catalog (`TaxonomyTerm`: one line per Key with all its spellings `Variants`, `Items`, `Seen`, the rule) / rules; `GET …/Names` = suggestions (not ignored, not renamed away) for the local editor's chips (`renderTermChips`, `[data-chip]`, loaded by `loadTermNames` when a local source is opened). **What is broken in Jellyfin 10.11.6 (verified with a read-only copy of `jellyfin.db`, `ItemValues` + `ItemValuesMap`)**: values are stored per exact spelling (`Docu` and `DOCU` = two `ItemValues` rows with the same `CleanValue`), while the genre entity id (hash of the name) is case-insensitive; rewriting items with one spelling relinks them to one row but the old rows stay with no item, and none of Jellyfin's maintenance tasks (optimise, clean-ups) removes them. The plugin does not write into Jellyfin's database. **Clicking a genre in jellyfin-web is `Items?GenreIds=<id>`, which finds nothing when the Genre entity (a `BaseItem`) does not exist** (verified: `Genres=<name>` found the episodes, `GenreIds` found none, `GET /Genres/{name}` created the entity and fixed it; the `/Genres` list does not create entities either): `TaxonomyService.EnsureGenres` calls `ILibraryManager.GetGenre(name)` for every genre of a managed item (in the `ItemUpdated/ItemAdded` hook, whatever the rules, and at the end of Apply; once per name and process, `Ensured`), and `TaxonomyTerm.Unopenable` flags a name whose entity comes back with another name (none seen so far, names with `/` and `-` work once the entity exists). **A rename is normalised at save** (`TaxonomyService.NormalizeTargets`, called by the PUT): the target is rewritten with the spelling the catalog gives the existing term, and a spelling rule (`X → X`) is added when that term exists under several spellings, otherwise renamed items kept their own spelling and Jellyfin listed two entries. Terms of items the plugin does not manage are never touched. Screen: per-line buttons `[data-act=replace|ignore|keep][data-key]` (no drop-down), filter chips `[data-filter]` in `#txFilters` (`inFilter`, `FILTERS`, `changed` = `isChanged`: rule differs from `t.Base` set by `markSaved`), `.tx-row[data-changed]`, merge bar inside the sticky `.tx-dock` with the save bar.
