# Dump sources

> Detail moved out of `CLAUDE.md` to keep the always-loaded file small. Read it when touching `SourceType = "Dump"`, `DumpStore`, coverage, name matching (user guide: `docs/DUMP_SOURCE.md`). `CLAUDE.md` still holds the rules that apply everywhere.

**Dump sources (`SourceConfiguration.SourceType = "Dump"`, imported from the former `Jellyfin.Plugin.DumpMetadata` plugin).** ONE call returns a whole catalogue of standalone episodes; the plugin keeps it in memory and finds each file in it. User guide: `docs/DUMP_SOURCE.md`.
- **`Services/DumpStore`** (singleton, log tag `📦 [DUMP]`) owns the catalogues, one per source prefix (`DumpCatalog`: entries with their raw JSON, indexes by id / slug / normalised title, pre-normalised names for the scoring). `GetCatalogAsync` downloads through a private `ResilientHttp` (so headers, retries, CORS flip, timeouts and the concurrency limit are the source's), under a per-prefix lock, and reuses the copy for `Dump.CacheMinutes`. The copy is valid only for the same **signature** (URL + the six paths): another URL or other paths = another dump, never served. A failed reload keeps the previous copy (`Error` returned next to it). **Pagination**: `Dump.PageParameter` / `FirstPage` / `MaxPages` (empty parameter = one call; a value containing `{page}` is a whole query parameter, name before the first `=`, value URL-encoded: `DumpStore.AppendPage`, which also drops the same parameter already typed in the base URL; `ResilientHttp.BuildUrl` keeps a base URL's query at the end so `/items/{id}` is never glued after it; the three fields live in the Général pane of the editor): pages are read in a loop and merged (deduplicated by id) until an empty page, a page with no new id (API ignoring the parameter) or a 404 after the first; a failed page or reaching `MaxPages` returns an error (never a half dump), and the three values are part of the signature. Nothing is persisted: a restart downloads again.
- **Serving, like a local source**: `ResilientHttp.GetStringAsync` answers a dump source with `DumpStore.ServeAsync` (no network): `{base}/items/{id}` → the entry's raw JSON, with `communityRating` = likes / (likes + dislikes) × 10 added when the `Dump.LikesPath` / `DislikesPath` give counters (an entry that already has one keeps it). `CustomApiClient.ResolveEndpoint` FORCES that address for a dump (`DumpStore.ItemEndpoint`; series/season get `/unsupported/{id}` = 404, "a dump holds standalone episodes only"), so the endpoints in a saved configuration do not matter; the metadata and image caches are skipped (served from memory) and missing paths log at Debug like a local source. Providers, images, the mapper, taxonomy rules and the cast overlay therefore work unchanged on `{prefix-id}` tags.
- **Matching a file with no tag** (`DumpStore.ResolveAsync(path, name, providerIds)`, only for items with a file): stored `custom` id → a tag of a dump source in the file name (a tag of another source returns null: not a file to guess about) → for sources with `Dump.MatchWithoutTag`: `FindCandidates` = a bare `{digits}` id (AUTHORITATIVE: absent from the dump = no match and no guessing; `{1080p}` is just noise) → exact slug → exact normalised name (also "name + episode number" for a `SxxExx`) → fuzzy `ComputeScore` over every entry (token overlap 55 + 20 pts, glued `search_titles` substring 50-95 depending on the confirmed episode number, +5 bonuses; an `SxxExx` the entry does not confirm is capped under the default threshold on purpose). The best score over all name-matching sources wins; below `Dump.MinScore` nothing matches (the Identify screen uses `SearchAsync` with the threshold lowered to 40). `CustomEpisodeProvider`, `CustomMetadataProvider` (movies: the dump is checked FIRST, its legacy single-source path is untouched) and `CustomImageProvider` call it when they found no tag. **A name match is stored as `ProviderIds["custom"]` = `prefix-id` on the item** (the only case where a file-backed episode gets one), so later refreshes go straight to the entry and the coverage view counts the file as owned. `GetSearchResults` of the episode and movie providers returns the dump's best 5 as search results carrying that `custom` id (Jellyfin's Identify screen).
- **Mapping additions made for it, usable by any source**: `FieldMapping.Studio` (text / list / `x[].name` → `CustomMetadataResponse.Studios` → `Studios` of episodes and movies; carried by `MetadataMerger` and `MergeOverride`) and `FieldMapping.OverviewIsHtml` (`HtmlText.ToPlainText`: br/p/li → text, entities decoded, tags dropped, doubly-escaped `\n` and invisible characters handled; applied after the entity decoding).
- **Coverage** (`Api/DumpController`, admin only, `CustomMetadata/Dump/`): `POST Test` (the unsaved source, force-downloads, counts entries, and for a `FileName` returns the candidates with score / accepted / how; a name with a video extension is matched like a file), `POST Reload?prefix=`, `GET Sources`, `GET Coverage?prefix=&status=missing|owned|all&group=&tag=&year=&q=&sort=group|name|date|id&desc=&page=&pageSize=&refresh=` (totals, per-group coverage, the 120 commonest tags, years, and ONE filtered page: a dump can hold tens of thousands of entries), `GET Export` (same filters, CSV with a BOM, formula-looking cells prefixed with `'`). **Coverage cache** (`Services/DumpCoverageCache`, hosted service, log `📦 [DUMP] Coverage '<prefix>:<slot>' computed in N ms`): slots `rows` (the rows linked to the library: `RowsOf` + `LinkOwned` + `LinkContainers`), `summary` (totals, groups, tags, years, series groups) and `index` (id → image URL, not library-dependent) are valid for the SAME `DumpCatalog` instance (a reload makes a new one, so the dump's own cache drives it), the same `MappingKeyOf` + `DumpSettings` JSON, and the same library version (`ItemAdded/Updated/Removed` of non-virtual Episode, Movie, Series, Season bump a counter; 10-minute expiry as a safety net). The kept lists are shared and read-only: never modify a `DumpRow` after `LinkedRows`. **Tags** of a row go through `JsonFieldMapper.ReadStringList` (the mapping's own list reader, no logging), with `TagsItemField`, in the row cache key; the editor's click-to-fill (`MAP_SECTIONS`) includes the `dump` pane except `srcDumpItems` (relative to the whole response). **Series page recap** (`renderCrumbs` in `missing.html`): `DumpSeriesCoverage.Tag` (`prefix-seriesId`, only for a series grouped by the dump's series id) and `ImageId` feed the picture and the "Copier le tag" button; "Copier les N noms" copies the `.dc-entry[data-file]` shown. `DumpController.LinkContainers` links a series grouped by the dump's series id to the library Season (preferred) or Series whose own folder name or stored id is `prefix-seriesId` (`DumpRow.LinkItemId/LinkKind/LinkSeries/LinkSeason`, applied after `LinkOwned`, one library query only when a row has a series id): `LibraryItemId` / `LibraryItemKind` on the card and the series info, a « Ouvrir … dans Jellyfin » link on the page. The plugin does not resolve a series tag for a dump (series are 404): it is only a name to put in a folder. **Series**: `Dump.SeriesIdPath` / `SeriesNamePath` (optional) put the entries that share an id in one series (`DumpRow.SeriesId`, key `s:<id>`, `DumpController.GroupSeries`; name = the name path, else the most common numberless title, else the shared words, else "Série <id>"); entries without an id go through the grouping by trailing number (`GroupSeriesByName`, `SeriesMinEntries`). Both paths are part of the row cache key. The light row of each entry (date, tags, image through the video mapping's paths) is computed once per catalogue copy and mapping (`ConditionalWeakTable`). **Owned** = a non-virtual Episode or Movie whose `custom` id is `prefix-id` or whose own file name carries that tag.
- **UI**: `config.html` handles type `dump` in the existing editor (`data-types="dump"`, `#editorView[data-source-type="dump"]`): the "Catalogue" section (`#srcDump*`), the video mapping and Réseau/Miniatures, a test panel with a file-name test (`testDump`, candidates with score bars, "rapproché" / "trop bas", advice under the threshold) above the usual id test (`DUMP_DEFAULTS`, `DUMP_VIDEO_MAPPING`, `fillDumpFields` / `readDumpSettings` / `applyDumpSourceDefaults`; the endpoints are forced to `/items/{id}` and the others emptied on every save). The card says "Dump" and links ("Couverture", via `sessionStorage['cm-missing-dump']`) to `missing.html`, which has a **Séries / Catalogues** switch (shown only when a dump source exists; the whole series view lives in `#seriesView`, the catalogue in `#dumpView` with its own script: filters debounced, chips, group cards, cards/list shared with the episodes' `cm-missing-view` choice, pager, CSV downloaded with `fetch` + `X-Emby-Token`). `checkLibraryProviders` also checks the **Movie** type of movie/mixed libraries when a dump is enabled, and skips series/seasons when only dumps are active; the setup guide drops the "tag a series folder" step for a dump-only setup.
- **Targeted refresh of a dump** (`SourceRefreshService.StartDump`, chosen when the prefix belongs to an enabled dump source): never by tag. It lists the Episode / Movie files of the chosen libraries (`SourceRefreshRequest.LibraryIds`, one `AncestorIds` query per library; `Types` = `episode` / `movie`), keeps those `DumpStore.ResolveAsync` gives to this prefix (status `Phase` "scan", `Scanned`, `Matched`), then `ApplyDumpAsync` (phase "refresh") **writes them directly, WITHOUT `item.RefreshMetadata`**: a full Jellyfin refresh calls every other provider of the library (TMDb over the network), probes the file and rebuilds the images, seconds per item for data that is already in memory (measured: ~5 ms direct against 80-500 ms on local 750 MB files). It asks the plugin's own provider (`IProviderManager.GetMetadataProviders<T>(item, libraryOptions).OfType<CustomEpisodeProvider | CustomMetadataProvider>()`, so a provider unticked in the library applies nothing, with a Warning) for the metadata, `CopyMetadata` sets only the fields returned (tags / genres / studios unioned, people merged with the existing ones, a locked item untouched), then `UpdateToRepositoryAsync(MetadataImport)` (which fires the taxonomy and chapter hooks) and `ApplyImagesAsync` when images are replaced. The page (`config.html`) shows a library picker (`[data-libpick]`, choice kept in `localStorage['cm-refresh-libs:<prefix>']`) and Épisodes / Films boxes for a dump group; the click handler reads only the `[data-rf]` boxes that exist (it used to throw on the missing Séries / Saisons ones, so the button did nothing). Logs: `🔁 [SOURCE REFRESH] 📦 …` (files listed in N ms, recognised in N ms, done in N ms) and `⏱️` per item. A dump entry served to a provider logs `📦 [DUMP] Entry … read from the catalogue in memory`, never `📡 [API CALL] GET` (no request is sent: checked with a hit counter on the mock, route `/__hits`).
- **Not done**: the Diagnostic page does not replay a name match; no on-disk copy of the dump.
