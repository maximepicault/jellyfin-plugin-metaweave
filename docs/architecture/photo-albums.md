# Photo albums and photos

> Read it when touching `ContentAlbums`, the album / folder / photo providers, `PhotoLibraryService`, the local albums or their editor.

- **Content of a source** (`SourceConfiguration.ContentVideo` default true, `ContentAlbums` default false; API and local only). `SourceResolver.GetSourceByPrefix(prefix, SourceContent)` filters on it: the video providers ask for `Video` (the default), albums for `Albums`, image downloads for `Any`. A dump never answers for albums.
- **What Jellyfin makes of folders**: a folder directly holding images is a `PhotoAlbum`; one holding only sub-folders is a plain `Folder`. Both are albums for the plugin (`SourceRefreshService.IsAlbum`: `PhotoAlbum` or exact type `Folder`). Libraries: « home videos and photos » with photos enabled; the library options list no metadata fetcher for `PhotoAlbum`, the providers run anyway, so the source's content switch is the only switch.
- **Albums** (`Providers/CustomPhotoAlbumProvider`, `AlbumProviderBase<T>`): tag of the folder's own name, else the stored `custom` id; `CustomApiClient` item type `album` (`AlbumEndpoint`, `AlbumFieldMappings`; a local source's are imposed). Images through `CustomImageProvider` (`Supports` only for a tagged folder). A local `folder.jpg` stays first. No native cast: `Photo` and `PhotoAlbum` have `SupportsPeople=false` (see « People »).
- **Photos** (`Providers/CustomPhotoProvider`): an `ICustomMetadataProvider` with order 100, so it runs after « Embedded Information » (EXIF), which rewrites overview, tags, genres… at each run; `IForcedProvider` to run whenever that one does. Only filled fields are written. A locked item is skipped, locked fields are skipped (EXIF itself does not respect field locks, so only the item lock keeps a typed value).
- **Videos of an album** (`CustomAlbumVideoProvider`, same base class `AlbumMediaProviderBase<T>`): exact type `Video` only, never an extra (`SourceRefreshService.IsAlbumMedia`: films and episodes are types of their own); order 1000, after Jellyfin's probe of the file. Identified and mapped exactly like photos (same list, same `PhotoEndpoint` and `PhotoFieldMappings`); no image from the source. The targeted refresh type `photo` takes them too.
- **Which data** (`Services/PhotoLibraryService`): (1) own tag in the file name → item type `photo` (`PhotoEndpoint`, API sources only, empty = off); (2) else the file name (any case) in the list of the **direct** parent folder's album answer (`PhotoListPath`, `PhotoFileField`, read by `Services/PhotoList`). `PhotoInheritAlbumTags` adds that album's tags. The album's raw answer is remembered 30 s (not for local sources) and dropped when a user refresh reads the album again.
- **A plain library scan does not apply a source change**: targeted refresh (`POST CustomMetadata/Refresh`, types `album` and `photo`; photos of the matching albums come with them; a photo's image is never replaced), or a refresh in Jellyfin.
- **Local albums**: `LocalContent.Albums` (`LocalAlbum`: node fields, `Studio`, sub-`Albums`, `Photos`), served as `/albums/{id}` with a `photos` list (entries with nothing typed are left out). Ids unique among albums; depth limited to `MaxAlbumDepth` (10, the page too: the REST layer limits JSON depth). The tree is only an arrangement: Jellyfin's folders decide the real nesting.
- **Page** (`config.html`): content check boxes (`updateContentUi`, `data-content` on menu entries), sections `album` and `photo` (API, sub-tabs of the menu entry `group-albums`), « Albums » = the local content pane in `localMode = 'albums'` (`renderAlbumTree`, `renderAlbumDetail`, `readLibraryPhotos` → `GET CustomMetadata/Local/LibraryPhotos?tag=`).
- **Test**: `tools/ui-test/albums-real.mjs <url> <out_dir> <host_media_dir>` (own media, fake API on port 8766, library and sources; restores the configuration).
- Not built: dump sources, local data laid over an API album.

## People

- **Why a store of our own**: Jellyfin keeps no cast on a photo or an album, and `UpdatePeopleAsync` on one stores nothing (checked on 12.4). `Services/AlbumCastStore` → `album-cast.json`, by item id: `Members` (name, role, type, photo address, relative for an uploaded one) and, for videos, the keys written into Jellyfin.
- **Resolution** (`Services/AlbumCastService.ResolveAsync`), added together: the element's own (album: API `cast`, or `LocalAlbum.Cast`; file: the `cast` of its list entry, or `LocalPhoto.Cast`), the People screen by tag (types `album` and `media` of `CastOverlayStore`), and what each album folder above gives to its whole content (local: `LocalCastEntry.All`; API: `PhotoInheritAlbumCast`, every ancestor; People screen: `Cascade`).
- **Applied** by `CustomAlbumCastProvider` (albums and folders) and the media providers, whenever they run; by « Appliquer » of the People screen (`AlbumKeys`, `MediaKeys`: links only, no refresh); by the targeted refresh. Videos: `UpdatePeopleAsync`, replacing or taking back only what the plugin wrote (a person typed in Jellyfin stays, even if a link names them too). With `EnableCasting` off nothing is applied and the routes answer nobody; a locked item is skipped. When an API source that had to be asked does not answer (network, refusal, server error, unreadable answer), the links already known are kept; « unknown to the source » (404, 410) is an answer and takes them back.
- **Routes** (`Api/AlbumCastController`, any signed-in user, over what that user sees): `CustomMetadata/AlbumCast/Item/{id}`, `People?parentId=`, `Items?person=&parentId=`.
- **Theme**: chips on the album page and in the viewer; a people bar on the library (one person at a time, `pjperson=` in the address); a section added to jellyfin-web's person page (only people Jellyfin knows have one: someone linked to photos alone has no such page, the library filter is the way to them).
- **Test**: `tools/ui-test/album-people-real.mjs <url> <out_dir> <host_media_dir>` (fake API on port 8768).
- Not built: removal of the records of deleted items (never shown: visibility is checked), people in the stock web client and the apps for photos and albums.

## The theme's screens (`theme/projection-photos.js`, section 19 of `projection.css`)

- Served as `CustomMetadata/Theme/projection-photos.js`, inserted with the other theme scripts (setting `EnableThemeScript`); acts only when the stylesheet defines `--pj-photos: 1`, never in the TV layout. Reads only, the favourite button apart. No server route of its own: Jellyfin's `/Items`, `/Items/{id}/Ancestors`, `/Items/Filters`.
- **Routes**: the library's « Dossiers » view (`#/homevideos`, no `tab` or `tab=0`) and `#/list?parentId=` of a `PhotoAlbum` or `Folder` below a `homevideos` library (the ancestors say which). Anything else stays stock; the screen is appended hidden and revealed once it is known to be a photo one (`reveal`).
- **Library**: one level at a time; a search, a tag or a genre (one of each at most) searches every depth. On this screen the app bar's second row is hidden (`html.pj-ph-libon`) and the other views are links in the header (`VIEWS`).
- **Album**: head picture = backdrop, else cover, else first photo, else a photo from further down, shown whole (`contain`) between the ambient light of its colours (`window.__projectionColours`); under 1.25 of ratio its edges are not faded (`pj-ph-narrow`). The description sits under the title, folded to four lines with « Lire la suite » when longer (`overview`). Photos come 120 at a time. An album without a cover shows its first photo (one request per such card).
- **Viewer**: appended to `body`, takes the keyboard at window capture (arrows, Escape, space); column with the fields of `/Items/{id}`, the file name only (never the server's folders).
- **Pictures sooner**: the server makes each requested size from the original (0.3 to 1.8 s per image for a 24 MP photo on an 8-core machine, first time only). So pictures are asked in a few fixed sizes (next point); the head picture is requested as soon as the album item is read and its 640 px version (the card's) shows first; thumbnails are `fetchpriority="low"` (HTTP/1.1 gives a host six connections); the viewer shows the wall's thumbnail (`pj-ph-low`), then the large one, then fetches both neighbours (`lookAhead`). The library does not wait for `Items/Filters` nor for the people.
- **Fixed sizes**: the screens ask only for `CARD` (640 wide), `TILE` (1200 × 360), `SCREEN` (1920 × 1080) and `WIDE_SCREEN` (2560 × 1440, past 2000 × 1150 device pixels), quality 90. Changing one means changing `Services/ImagePreparationService` too.
- **Prepared in advance** (`PrepareLibraryImages`, `PrepareWideScreenImages`; both off by default): the task `CustomMetadataPrepareImages` (daily, 5 h; only with `EnableThemeScript`) calls Jellyfin's `IImageProcessor.ProcessImage` for every `homevideos` library holding a photo, with the formats of a current browser, so the cache entries are those a browser then asks for. A quarter of the processors at a time. Only files under the cache folder are touched: one older than 20 days is dated again, because « Clean Cache Directory » removed a 40-day-old one and kept a 25-day-old one (observed on 12.4). Bench: 1715 pictures (about 850 photos and videos), 9 min 5 s on 8 cores, 127 MB.
- **Videos**: photos and videos share the wall, the viewer and the paging, and are counted apart (`howMany`). The viewer plays the file as it is (`/Videos/{id}/stream?static=true`): no transcoding, and no playback position or « seen » reported to Jellyfin; on a media error it offers the item's page. The slideshow waits for a video's end. A library or folder is taken over only when its library holds at least one photo: a library of videos only stays stock.
- Counts on the cards are Jellyfin's `ChildCount` (« éléments »: sub-albums and photos together).
- **Test**: `tools/ui-test/photos-library-real.mjs <url> <out_dir> <host_media_dir>`. Depends on jellyfin-web 12: page id `homevideos`, `#library-view-menu`, `.alphaPicker`, `viewshow`.
