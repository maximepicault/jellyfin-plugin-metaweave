# Local sources

> Detail moved out of `CLAUDE.md` to keep the always-loaded file small. Read it when touching `SourceType = "Local"`, `LocalSourceStore`, the local editor, image upload/gallery/sub-folders, targeted refresh, overriding an API element. `CLAUDE.md` still holds the rules that apply everywhere.

**Local sources (`SourceConfiguration.SourceType = "Local"`).** A source whose series, seasons and episodes are typed in the plugin instead of coming from an API, so a forced metadata refresh in Jellyfin can't wipe them, and episodes you don't have yet can be declared (they show up as missing episodes). Chosen at creation in `config.html` (the "Ajouter une source" button first offers API / Locale).
- **Data**: `Services/LocalSourceStore` keeps one JSON file per source, `DataFolderPath/local-sources/{LocalDataId}.json` (a stable random id, independent from the renamable prefix; atomic write plus a `.bak`; deleting a source renames the file to `.deleted`). Series → seasons → episodes, each node with a generated 6-character `Id` that is the `{prefix-ID}` tag to put in the folder or file name. `Normalize` keeps valid unique ids, drops duplicates and dates that aren't `yyyy-MM-dd`, and decodes HTML entities in titles, overviews, tags and genres (`HtmlText`), so pasted text (`Q&amp;A`) is stored clean and the editor and "Copier le nom" never show `&amp;`; `Load` does the same for files saved before. The served JSON is decoded once more by `JsonFieldMapper` (harmless).
- **Serving**: `ResilientHttp.GetStringAsync` returns `LocalSourceStore.Serve(...)` for a local source (no network), with the default JSON shape (`title`, `overview`, `premiereDate`, `tags`, `genres`, `poster`, `thumb`, `indexNumber`, `duration`, `preview.url`) on the default endpoints (`/series/{id}`, `/sources/{id}`, `/sources/{id}/videos`, `/videos/{id}`; base `local://local`, the host is ignored). Providers, images, missing episodes and the cache hash therefore work unchanged. `CustomApiClient` skips the metadata/image cache for local sources so edits show up immediately.
- **The endpoints and mappings of a local source are imposed**: `config.html` (`applyLocalSourceDefaults`) writes them on every save, and the API-only sections (Endpoints, mappings, Réseau, test panel) are hidden with `data-only="api"` in the editor (`#editorView[data-source-type]`).
- **Editor**: `Contenu` section = tree (series → seasons → episodes, `＋` buttons, collapsible) next to a detail form with copy buttons for the tag and a suggested name, plus a paste-a-list import per season. `Api/LocalSourceController` (`GET/PUT/DELETE CustomMetadata/Local/{dataId}`, admin-only) reads and writes the whole tree: saving a local source PUTs the content first, then persists the config. After saving, a notice offers "Analyser maintenant".
- **Test without Docker**: `tools/ui-test/config-local-ui.mjs <out_dir>` loads the real `config.html` in headless Chrome with an in-memory fake `ApiClient` (134 checks: type choice, editor sections, tree, bulk add, image upload, save order, imposed mappings, reopen, delete, API editor unchanged). It does not test the Jellyfin theme or the `emby-*` elements.
- Verified end to end in the 10.11.6 container (2026-11-13): series/season/episode metadata and images, a file with two tags (title and number range from the first, tags merged), HTML entities decoded, and two undeclared episodes created as virtual episodes with thumbnails. `tools/ui-test/config-local-real.mjs <url> <out_dir>` takes screenshots of the local editor in the real jellyfin-web (it needs a local source already in the config).
- jellyfin-web specifics met here: `<textarea is="emby-textarea">` lays its label and field side by side, so the editor uses plain styled `<textarea>`s.
- **Image upload**: each image field (poster, backdrop, logo, banner, episode thumbnail) takes a web URL or an uploaded file. `POST CustomMetadata/Local/{dataId}/Image?node={id}` (raw bytes, 8 MB max, type read from the first bytes: JPEG, PNG, WebP, GIF) stores `local-sources/{dataId}-images/{nodeId}-{random}.ext` and returns `local://img/{dataId}/{file}`, saved in the node's field; `GET …/Image/{file}` serves it for the editor preview (`?api_key=`). `CustomImageProvider.GetImageResponse` and `CustomApiClient.DownloadImageAsync` read `local://img/…` straight from disk (no network; the portrait→16:9 conversion still applies). `Save` prunes unreferenced images older than one day; deleting a source renames its image folder to `.deleted`. The editor uploads with `fetch` and `X-Emby-Token`: `ApiClient.ajax` does not send a raw file correctly (found in the real jellyfin-web, the fake-ApiClient test could not show it). Limit: Jellyfin's own image picker can't preview `local://` images (they download fine).
- **Local source sharing an API source's prefix**: `SourceResolver.GetSourceByPrefix` returns the API source first (`OrderBy(IsLocal)`), and `FindOverride` also matches a plain node id (`1234`) of a local source whose prefix equals the tag's, so `{fny-1234}` calls the API then lays the local data over it. `MergeLocalEpisodes` treats a plain local episode id of a same-prefix source as the API episode's id. `CastCatalog` does not skip a local prefix that an API source also uses.
- **Targeted refresh** (`Services/SourceRefreshService`, `POST CustomMetadata/Refresh` `{Prefix, Types, ReplaceImages, Tag?, IncludeChildren?}`, `GET …/Status`, admin only): finds Series/Season/Episode items whose OWN file/folder tag (or `custom` id for virtual episodes) has the prefix, then refreshes them in a background task, series → seasons → episodes, one at a time (never `QueueRefresh`, see CastApplyService), `ReplaceAllMetadata`, images replaced when `ReplaceImages` (the button ticks it by default; the REST default is false), `IsAutomated = false` so the plugin's cache is bypassed. One run at a time (static semaphore, a second request gets a `Message`). With images replaced, each item logs `🖼️ '<name>': images replaced|UNCHANGED (before: … | after: …)` (type, file, last write of every image), the first thing to read when someone reports that a refresh did not change an image. The Sources tab groups the cards by prefix (`renderSourcesList`, `.cm-group-head`), the button polls the status. Test: phase D of `tools/ui-test/local-override-real.mjs`.
- **Image gallery** (`LocalNode.Gallery` = `{Type: Primary|Backdrop|Logo|Banner|Thumb, Url}`, cleaned by `CleanGallery`, served as the `images` array: `CustomApiClient` gives a local source's mapping `ImagesArray=images` when it has none, `config.html` imposes it too). `CustomImageProvider.GetImages` turns `local://img/…` into `{request host}/CustomMetadata/Local/{dataId}/Public/{file}` (anonymous endpoint of `LocalSourceController`, random file names only): jellyfin-web 10.11 previews `Url` (it ignores `ThumbnailUrl`) AND Jellyfin's `DownloadRemoteImage` downloads `Url` with its own HTTP client (an absolute address is required, `GetImageResponse` is not used there). The host comes from the current request (`IHttpContextAccessor` through `IServiceProvider`, never constructor-injected: a missing registration would break the provider), else `GetLocalApiUrl("127.0.0.1")`. `GetImageResponse` maps the address back to `local://`. The editor's "Appliquer les images" button calls the targeted refresh (`Tag`, `IncludeChildren`, `ReplaceImages`). Test: `tools/ui-test/local-gallery-real.mjs <url>` (the test container maps 8097→8096, so it lists with `Host: …:8096`).
- **Backdrops stay landscape** (`Services/ExifOrientation`): a JPEG with landscape pixels and an EXIF rotation of 90° (Orientation 5–8; a portrait picture turned landscape in an editor that kept the tag) is shown portrait by browsers and Jellyfin's apps, so the Projection theme drops it. Whatever the plugin hands Jellyfin AS A BACKDROP gets the tag reset to 1 in place (no re-encoding): the provider gives an uploaded backdrop the address `…/Public/{file}?landscape=1` (the picker's preview and Jellyfin's download), `GetImageResponse` honours it, and `SourceRefreshService.ApplyImagesAsync` and the people backdrops (`CastApplyService`) do the same. The uploaded file itself is not changed, and posters and other types keep their tag (a phone photo is the same bytes and must stay as shot). Already applied backdrops are fixed by "Appliquer les images" (the SHA-256 differs). Test: `tools/ui-test/local-backdrop-orientation-real.mjs <url>`.
- **Default image and backdrop carousel**: the single fields (`Poster`, `Backdrop`, `Logo`, `Banner`, `Thumb`) are the defaults; the default of a type is that field when filled, otherwise the FIRST gallery image of the type (badge in the editor). A gallery image is selected by clicking it (`galSel`), then "Utiliser comme image par défaut" swaps it with the field (`GALLERY_FIELD`; Primary ↔ `Poster`) or, when the field is empty, moves the image into that field and out of the gallery (a Backdrop instead moves to the first place of the slideshow); "Retirer" acts on the selection too. A normal refresh keeps only as many backdrops as the library allows (usually one), so `SourceRefreshService.ApplyImagesAsync` runs after the refresh of every item when images are replaced, because Jellyfin's own "replace all images" does NOT beat an image file already in the media folder (a `poster.jpg` kept the old Primary: reproduced, the log said `Jellyfin refresh left UNCHANGED the images`). For Primary, Thumb, Logo and Banner it takes the FIRST image of `CustomApiClient.GetImagesAsync` (API, then local; for an episode a Thumb stands in for a missing Primary), else the first image of the matching sub-folder (`Primary/`, `Logo/`… of a series/season folder), and saves it with `IProviderManager.SaveImage` only when its SHA-256 differs from the item's current file. Backdrops: all of them (API, gallery, `Backdrop/` folder, de-duplicated), extra old ones removed when there are at least two. Test: `local-gallery-real.mjs` (2 backdrops → `BackdropImageTags` = 2). **`IProviderManager.SaveImage` only writes the file and sets the path on the item in memory**: `ApplyImagesAsync` ends with `item.UpdateToRepositoryAsync(ImageUpdate)` when it changed something, otherwise the database keeps the old image list and the images vanish when Jellyfin reloads the item (restart or cache eviction; the REST API answers from memory and hides it, and merely opening the item in jellyfin-web saves it, so only a read of `jellyfin.db` right after the refresh shows the bug). Candidates of a type are tried in order until one can be read (source images, then the sub-folder). An old image file left in the media folder (`poster.jpg`, not deleted by Jellyfin's `ImageSaver` unless the library saves artwork with the media) wins again at the next scan: counted in `SourceRefreshStatus.LocalFilesKept`, logged at Warning with the paths, shown in amber under the button (`.cm-group-warn`). Test: `tools/ui-test/refresh-persist-real.mjs <url> <series_root_dir> <images_dir> <jellyfin.db>` (image fetchers switched off in the library so that the plugin applies the images itself; reads the database read-only with `node:sqlite`).
- **Gallery size and multi-selection**: `CleanGallery` keeps at most 1000 images per node (it was 60: the rest was dropped at save). The editor keeps `galMulti` next to `galSel` (Ctrl/Cmd+click toggles, Shift+click selects a range, `data-gal-act` `all`/`sametype`/`none`/`mflag`/`mremove`; the type menu applies to the whole selection). Test: `tools/ui-test/config-local-ui.mjs`.
- **Demoted images** (`LocalImage.NoDefault`, served as `"noDefault": true` in the `images` array, read into `ImageInfo.NoDefault` by `JsonFieldMapper`): a gallery image kept but never applied as the default of its type. The editor's "Ne plus utiliser par défaut" button (on a default field image or the first gallery image of a type, not for Backdrops) sets it; `ApplyImagesAsync` skips flagged images (so an episode without an unflagged Primary falls back to its Thumb) and `CustomImageProvider.GetImages` lists them last. Not covered by an automated server-side test.
- **Image sub-folders** (`Services/FolderImages`, `Api/FolderImagesController`, `Providers/ImageFolderIgnoreRule`): a tagged Series/Season folder may hold sub-folders named after the image types (Primary, Backdrop, Logo, Banner, Thumb + a few French names, case-insensitive). `CustomImageProvider.GetImages` lists their images LAST (the default stays the first one) as `{request host}/CustomMetadata/FolderImages/{itemId}/{folder}/{file}`: anonymous GET (preview + Jellyfin's own download), stateless (the item gives the directory, `FolderImages.TryResolve` accepts only an image file directly inside an image sub-folder: no separators, no `..`, other folders 404). `GetImageResponse` reads them from disk for the library-refresh path. `POST CustomMetadata/FolderImages/Import` (`{Tag, DataId, NodeId}`, admin) copies them into the plugin's image storage and returns gallery entries; the editor's "Importer depuis les dossiers" merges them by `LocalImage.Name` ("Principal/a.jpg", so a second import adds nothing). **Jellyfin turns every sub-folder of a series folder into an empty Season**, so `ImageFolderIgnoreRule` (`IResolverIgnoreRule`, discovered like the providers) ignores image-named folders below a Series/Season whose own name carries a `{prefix-id}`; the existing empty seasons disappear at the next scan. Episodes are files: no image folders for them. Test: `tools/ui-test/local-folder-images-real.mjs <url> <series_folder> <images_dir>` (writes in the mounted media folder and cleans up); screenshots: `local-gallery-shots.mjs` with `SERIES_DIR`.
- **Local node ids** (series, season AND episode: the editor offers the "Identifiant" field on all three since 2026-11-17, it used to hide it on episodes) are unique per LEVEL (`LocalSourceStore.Normalize` keeps one used-set per series/seasons/episodes), valid pattern `^\w[\w-]{0,99}$`; the editor keys elements as `s:id` / `n:id` / `e:id` (`nodeKey`, `findNode`) because a series and its season may share an id. `LocalSourceStore.IsFullTag` / `isFullTag`: a hyphenated id whose first part is a configured source's prefix is that source's full tag.
- **Overriding an API element** (`LocalSourceStore.FindOverride`, applied in `CustomApiClient.GetMetadataAsync`/`GetImagesAsync` after the cached API answer, `MergeOverride` works on a copy): the Id of a local **series, season or episode** may be `prefix-id` (regex `^\w{1,20}-\w{1,40}$`), the tag of an element of another source. Local non-empty fields win, local images come first, the API still fills what the local node leaves empty. For a season, `MissingEpisodeService.AnalyzeSeasonAsync`: an API with **no** `EpisodeListEndpoint` takes the local list as is (source swapped for the local one, episode keys `loc-…`, `SeasonMissingReport.EpisodePrefix`); an API **with** a list stays the base and `MergeLocalEpisodes` lays the local episodes over it (same `prefix-id` = field override, anything else is added with `EpisodeListItem.Key` = its own tag; the local data never removes API episodes; the merged `RawJson` must stay valid JSON, the cache parses it back). `MissingEpisodeEntry.Tag` is the full tag `missing.html` copies. A local episode whose id is `prefix-id` keeps that tag as its key (`MissingEpisodeService.EpisodeKey`, local sources only: an API id may contain a hyphen), so it stands for the file tagged with the API's id and overrides that episode's metadata (`CustomApiClient.LocalOverride`, kind `episode`). An imported episode keeps `ApiBase` (the API values at import time); `LocalSourceStore.DropUnchangedFromApi` removes from the served JSON every field still equal to it, so only what the user changed overrides the live API (a copy would hide later API changes). Tags/genres/cast of a series/season override are unioned (`MergeOverride`). The editor's "Synchroniser la liste" button (season with a `prefix-id` id) calls `POST CustomMetadata/Local/ImportEpisodes` (`{Tag}`, nothing saved) and merges the API list into the season: missing episodes added with their API tag, empty fields of existing ones filled, typed values never overwritten, never automatic. Test: `tools/ui-test/local-override-real.mjs <url>` (REST only, restores the config).
