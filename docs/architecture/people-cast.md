# People directory and episode cast

> Detail moved out of `CLAUDE.md` to keep the always-loaded file small. Read it when touching `PeopleStore`, `CastOverlayStore`, `CastApplyService`, `people.html`, cast cascade. `CLAUDE.md` still holds the rules that apply everywhere.

**People (cast directory).** Cast is its own thing, not tied to a series/season/episode source. Four source types now exist (`SourceType`): `Api`, `Local`, `Dump` (see above), `People`.
- **`People` source** (`SourceConfiguration.IsPeople`): `BaseUrl` + headers + network like an API source, plus `PersonEndpoint` (default `/people/{id}`, one person per call) and `PersonMappings` (`Name`, `Photo`, `Bio`, dotted paths, plus `PhotoBaseUrl`: where a photo PATH lives when it is not on the API, a prefix or a `{value}` template, resolved by `Services/PersonPhotoUrl`). `SourceResolver.GetSourceByPrefix` skips them, so a file tag can never select one. `CustomApiClient.GetPersonAsync` fetches a person (relative photo URLs completed with `BaseUrl`, entities decoded); the editor's test button has a `person` type (`SourceTestResult.Person`). An identifier is only valid for its own source (`pe-123`).
- **Directory**: `Services/PeopleStore`, `DataFolderPath/people.json` (atomic write, `.bak`). A `Person` has an internal 6-character `Id` (referenced by episode casts), `Name`, `Photo` (URL or `local://img/people-directory/…`), `Bio`, `BirthDate`/`DeathDate` (normalised to `yyyy-MM-dd` by `PeopleStore.NormalizeDate`), `BirthPlace`, `Website` (http/https only), `Notes` (private, directory only; `Website` too: neither is sent to Jellyfin. `CastApplyService.SyncPersonItemsAsync`, started by every `Apply`, copies Bio → Overview, BirthDate → PremiereDate and ProductionYear (the birth year), DeathDate → EndDate, BirthPlace → ProductionLocations onto the Jellyfin person item found by `ILibraryManager.GetPerson(name)`, never erasing with an empty field; `PersonMapping` reads the first four from the API, empty path = not read) and `Links` (`Prefix` + `ExternalId`, one per source; a link belongs to a single person, the first that carries it). `FindMatch` dedupes by link first, then by name (`NormalizeName`: lowercase, no accents, no punctuation). Merging is a UI decision: `POST CustomMetadata/People/Fetch` returns the API data plus `MatchPersonId`/`MatchReason` (`link`/`name`) and saves nothing; the Personnes page then offers "Ajouter l'identifiant à cette fiche". Manual edits are never overwritten by a sync: "Compléter" fills empty fields only, "Écraser avec l'API" asks first. No automatic merge on save (it would break episode cast references); the list only shows a "doublon" badge.
- **Page** `Configuration/people.html` (`CustomMetadataPeople`, embedded, not in the main menu; button in `config.html`'s header): add by source+identifier or manually, search list, detail form (photo upload/URL, bio, identifiers with Compléter/Écraser/Retirer), sticky save bar, whole directory PUT at once (`GET/PUT CustomMetadata/People`). Photos are uploaded through the local-source image endpoint with the data id `people-directory` (`PeopleStore.ImagesDataId`). A chosen file first goes through a client-side cropper (`openCropper`/`showCropper`: square frame, drag, wheel and slider zoom, canvas output 512×512 JPEG, white background); only the cropped blob is uploaded. "Ajuster" re-opens it on an uploaded photo (a remote URL may refuse the fetch for lack of CORS). Animated GIFs lose their animation.
- **Remote images, backdrops, networks**: `PeopleController.Put` first downloads every http(s) `Photo`/`Backdrops` entry (`CustomApiClient.DownloadImageAsync`, the people source's headers when the person carries one of its links) into `people-directory` and stores the `local://` address; a failed download keeps the address. `Person.Backdrops` are written onto the Jellyfin person item by `CastApplyService.SyncBackdropsAsync` (`IProviderManager.SaveImage`, signature remembered in `cast-backdrops.json`). `Person.Networks` (`{NetworkId, Value}`) refer to `PersonNetworkStore` (`person-networks.json`, defaults until first save, `GET/PUT CustomMetadata/People/Networks`). Jellyfin 10.11 builds the person page links with `IExternalUrlProvider` classes found by reflection, one name per class and `ProviderManager.AddParts` replacing the lists, so `Providers/PersonNetworkUrlProviders.cs` is a fixed pool of 24 slot classes that read the N-th network on each call (no restart, 24 max); the icon is prefixed to the name because Jellyfin shows no image for a link.
- **Source mapping and the Réseaux tab**: `PersonMapping.Backdrops` (path to an array or one value, `ReadMany` in `JsonFieldMapper.MapToPerson`; resolved with `PhotoBaseUrl` like the photo) and `PersonMapping.Networks` (`{NetworkId, Path}` per network of `PersonNetworkStore`) end up in `PersonData` and in `POST …/People/Fetch`; `people.html` `applyExtras` merges them (`Compléter` adds what is missing, `Écraser` also replaces the backdrops). The config page's people pane loads the networks from `GET …/People/Networks` for the select of each row. The Réseaux tab of `people.html` edits the global list (saved by the one save bar with `dirtyNet`; `GET …/Networks/Defaults` feeds "reset"); order matters only for the slot pool.
- **Episode cast (local sources only for now)**: `LocalEpisode.Cast` = `{PersonId, Role, Type}` (`Type` = a Jellyfin `PersonKind` name). `LocalSourceStore.ResolveCast` turns it into the `cast` JSON array (`name`, `role`, `type`, `order`, `image`) read by the default mapping (`FieldMapping.CastImage` is new); unknown person ids are skipped. It reaches real and virtual episodes through the usual cast path, and `MetadataMerger` unions it with any API cast (dedup by name + type). `config.html` has a "Distribution" block in the episode form (type-ahead on the directory, role, type, "Appliquer à toute la saison").
- **Photos in Jellyfin**: `CastMapper` sets `PersonInfo.ImageUrl` for http(s) photos, and Jellyfin downloads it for the person (verified). An uploaded photo needs an address the server can read itself: `PeopleStore.JellyfinPhotoUrl` builds `{IServerApplicationHost.GetLocalApiUrl("127.0.0.1")}/CustomMetadata/People/Photo/{file}`, an **anonymous** endpoint (Jellyfin has no token) that only serves the directory's photos under random names.
- **Episode cast for API sources (overlay)**: the API is never modified. `Services/CastOverlayStore` keeps `DataFolderPath/episode-cast.json` = `{Key: "dm-a1v1" (the episode's `{prefix-id}` tag, lowercase, no braces), Cast: [{PersonId, Role, Type}]}` (atomic write, `.bak`, empty entries dropped, `NormalizeCast` shared with local sources). `CustomEpisodeProvider` resolves the entries for the file's tags (all of them for a multi-tag file) through `PeopleStore.ResolveCast` and adds them to the API cast with `MetadataMerger.WithExtraCast`, which works on a **copy** (the API response may be the cached instance: never mutate it). It applies live (no cache involved) and to virtual episodes too; it applies after the next refresh of the item ("Remplacer toutes les métadonnées" for existing real episodes).
- **Typed keys (series, season, episode)**: an overlay entry is `{Type: "series"|"season"|"episode" (default episode), Key, Cast}` and the type is part of the key (`CastOverlayStore.TypedKey`, `episode:dm-a1v1`): the same id can exist for a series and for an episode of one source. Series and season providers apply it too (`CustomSeriesProvider`, `CustomSeasonProvider`, keyed by their folder tag); `CustomSeasonProvider` now also sends the cast (API cast of the season mapping + overlay) to Jellyfin. **The season provider used to read the tag from `info.Name`**, which Jellyfin strips of `{prefix-id}`, so it never found an id on refresh: it now reads `info.Path` first (then `info.Name`, then the `custom` provider id), like the other providers. This also lets the season's API metadata (title, overview) apply on refresh, which it never did before. The Personnes page's "Par identifiant" view creates entries from a typed `{prefix-id}` even if the element is not in the library (shown as "pas dans la médiathèque pour le moment"). `CastApplyRequest` has `EpisodeKeys`, `SeasonKeys`, `SeriesKeys`. Not done: cast on local-source series/seasons (their editor only has it on episodes).
- **Distribution tab loading and cascade**: opening the tab only reads `GET …/EpisodeCast` (fast) and starts on "Par identifiant". The library listing (`GET …/People/Library`, slow on a big library) is loaded only by the "Parcourir la médiathèque" button (`loadLibrary`). People are added through a custom autocomplete (`#ppCastAdd` + `#ppCastSuggest`, photo/name/identifiers, arrow keys, Enter, Escape), not a `<datalist>`. **Cascade** (`EpisodeCastEntry.Cascade`, series and seasons only, saved in `episode-cast.json`): `Services/CastInheritance` gives an episode the cascading cast of its season then its series (`CastOverlayStore.GetCascading`), and a season that of its series; the own cast comes first, people deduplicated by id (`CastInheritance.Combine`). Parents are found through the library with exact types (`ILibraryManager.FindByPath(dir)` → Season/Series), never by guessing from folder names, because the same id can be used for a series and a season. A missing (virtual) episode has no path: `MissingEpisodeService` and `CastApplyService` call `CastInheritance.Register(customKey, seasonId)` before refreshing it, and the cast fingerprint of the missing-episode hash includes the inherited cast. `CastApplyService.Apply` queues every Season/Episode below a cascading series/season (`AncestorIds`) and `ExpandKeys` (sent by the page for keys whose cascade is on, or was before the change) also cleans the children when it is turned off; keys named in the request are applied even when their entry no longer exists. **Children with no identifier** never reach our providers (a file without a `{prefix-id}` of an enabled source is left to Jellyfin's own providers), so `CastApplyService.ApplyDirectAsync` writes their inherited cast straight into Jellyfin (`ILibraryManager.UpdatePeopleAsync`): it keeps the people that are not ours, replaces ours, never refreshes the item (a `ReplaceAllMetadata` refresh would wipe metadata other providers set), and remembers what it added per item in `DataFolderPath/cast-inherited.json` so that a removal or turning the cascade off takes back only those. `SyncUntaggedAsync` redoes it for every cascading series/season and runs at the end of the daily `MissingEpisodesTask`, which covers files added later; photos of people that Jellyfin does not know yet are not downloaded by this path. The test bench media has one tag-less episode (`gen.py`, "E08 Sans identifiant"). The checkbox is always usable (no library needed); its preview (`GET …/People/Children?type=&key=`, `CastCatalog.Children`) lists the tags below that one element only. Tests drive the focus with a dispatched `focusin` because `click()` does not focus and `focus()` is silent in the unfocused headless window.
- **Elements without any tag** (a whole series with no `{prefix-id}` at any level): `CastCatalog.Keys` gives them a fallback key `jf-<Jellyfin item id>` (`SyntheticKey` / `IsSynthetic`), so the catalog lists them and the overlay can hold their cast. They never reach a provider, so `CastApplyService.ApplyDirectAsync` writes their own overlay cast plus the inherited one straight into Jellyfin (`UpdatePeopleAsync`, never a refresh), and `SyncUntaggedAsync` (end of the daily task) redoes it for every `jf-…` entry and every untagged child of a cascading element. The key follows the item's path: a renamed or moved folder loses its distribution. Empty elements without tag (Jellyfin's "Season Unknown") are not listed.
- **One entry per person AND job** (`LocalSourceStore.SameCastEntry`): the same person can be actor and director of one element; `NormalizeCast`, `CastInheritance.Combine` and the overlay merge use that comparison, and the screens add someone already there with the next free job.
- **Choosing episodes**: `Services/CastCatalog` lists library episodes that carry a tag, grouped series → season → episode (`Key`, title, number, `IsMissing`), skipping Local and People prefixes (local episodes are edited in their source). Routes in `PeopleController`: `GET CustomMetadata/People/Library`, `GET/PUT CustomMetadata/People/EpisodeCast` (the PUT drops person ids no longer in the directory). `people.html` has two tabs: "Annuaire" and "Distribution des épisodes d'API" (season tree with word search, episode rows with a cast summary and count, inline editor: type-ahead on the directory, role, type, "Appliquer à toute la saison"); the one save bar PUTs the directory first, then the overlay. Saving them does NOT force a full reprocess of the missing episodes (it used to, which made every typo fix re-download all thumbnails and previews at the next analysis): the cast fingerprint in the episode hash is enough for "Analyser" to refresh only the virtual episodes whose cast really changed.
- **Propagation of later changes** (verified): names, photos and casts are copied into Jellyfin when an episode is enriched, so a rename in the directory or a changed cast does NOT reach already-enriched episodes by itself (not after a scan, not after "Analyser" for real episodes).
  - **Missing (virtual) episodes**: their hash in `MissingEpisodeCache.ComputeHash` includes a cast fingerprint (`MissingEpisodeService.CastFingerprint`: overlay entries resolved through the directory; local sources already carry the cast in the list's raw JSON), and the update branch calls `RefreshPeopleAsync` (metadata refresh with `ReplaceAllMetadata`, `ImageRefreshMode None`), because `UpdateVirtualEpisodeAsync` never touched the cast. So "Analyser" now updates them.
  - **Real episodes**: `Services/CastApplyService` + `POST CustomMetadata/People/Apply` (`{PersonIds, EpisodeKeys, Prefixes}`, all empty = everything that has a cast): finds the episodes depending on the change (overlay entries, local-source casts), then refreshes them one by one **in a background task** (a static semaphore serialises runs). Do not use `IProviderManager.QueueRefresh` for this: queuing several items at once threw `Guid can't be empty` inside `StartProcessingRefreshQueue` and silently dropped some episodes. The Personnes page tracks the persons and episode keys it changed and shows an "Appliquer aux épisodes" notice after saving; the local-source save notice has the same button (for that prefix).
  - Jellyfin keeps the old `Person` record after a rename (orphan until its own cleanup); not something the plugin touches.
- **Review fixes (before the first deployment)**: (1) no `RequestFullReprocess()` on directory/overlay saves (see above). (2) `people.html` shows a warning banner when `EnableCasting` is off (`#ppCastOff`), and the local episode "Distribution" block shows it too (`data-casting` attribute on the config page, set at `pageshow`): `CastMapper` silently drops every cast when the switch is off. (3) Editing the prefix of an existing source shows an inline warning (`#prefixWarn`, old and new tag) and asks for a confirmation on save: files tagged with the old prefix stop matching. (4) Distribution tab: the "Par identifiant" rows use the library title when known (tag as the second line), the series row says "Distribution de la série ›", a season with its own cast gets a "saison" badge, and the detail panel is capped at 980 px.
- **Not done**: cast on series/seasons, a real "merge two people" that rewrites episode casts, a list endpoint to bulk-import people, a way to copy a cast between a local episode and an overlay.
- **Tests**: `config-people-real.mjs <url> <out_dir> --quick` runs only the photo cropper checks (~10 s). All `tools/ui-test` scripts take a lock (`chrome-session.mjs`): one at a time, they share the container and its configuration. `tools/ui-test/config-local-ui.mjs` (55 checks, no Docker), `tools/ui-test/config-people-episodes-real.mjs <url> <out_dir>` (32 checks on the distribution tab (episodes, season, series, by id) and the apply notice; seeds its own People source, directory and distributions, and restores them; overrides `window.confirm`, a native dialog would block the CDP driving), `tools/ui-test/config-people-real.mjs <url> <out_dir>` (18 checks on the Personnes page in the real jellyfin-web, casting banner and width cap included; seeds and restores its own state; the mock API serves `/people/{id}` for `p1..p3`, `p3` having the same name as `p1`).
