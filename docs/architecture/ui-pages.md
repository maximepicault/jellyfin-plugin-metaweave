# Shared UI pieces and extra pages

> Detail moved out of `CLAUDE.md` to keep the always-loaded file small. Read it when touching the tab bar, Diagnostic page, click-to-fill mappings, in-page confirmation, setup guide, left-menu shortcuts. `CLAUDE.md` still holds the rules that apply everywhere.

**Shared tab bar, Diagnostic, click-to-fill (2026-11-16).**
- **Tab bar** (`.cmn-nav`, classes `cmn-…`): the same block (CSS scoped under the page id, HTML, `loadNavStatus()`) is copied in `config.html`, `missing.html`, `downloads.html`, `people.html`, `diagnostic.html` and `taxonomy.html`: change the six together. Six tabs (Configuration, Épisodes manquants, Téléchargements, Personnes, Diagnostic, Genres et tags), plain `<a href="#/configurationpage?name=…">`, the current one has `aria-current="page"`. Counters come from `GET CustomMetadata/Status` (`DiagnosticController`: sources, missing episodes and source errors of the last report, downloads waiting or running (or, when none, the failed ones, as an alert), people, total of the last diagnostic list; null = never computed, the pill is then hidden with `:empty`). In `config.html` the bar is inside `#listView`, so it is not shown while a source is edited. The tabs of a page itself are second-level pills (`.cm-tab`, `.pp-tab`).
- **Diagnostic** (`Services/DiagnosticService`, `Api/DiagnosticController`, `Configuration/diagnostic.html`, page `CustomMetadataDiagnostic`, NOT in the left menu). `POST CustomMetadata/Diagnostic/Element` `{Name, Kind}` replays six steps and stops at the first `fail` (states `ok` / `fail` / `info` / `skip`): tag (`TagParser.Extract` on the name alone), source (enabled API first, like `SourceResolver`; a disabled one is named), library (the item carrying the tag, then `ILibraryManager.GetLibraryOptions(item).TypeOptions` for our two provider names; no such item = `info`, not a failure), call (`CustomApiClient.TestSourceAsync`, no cache; the type comes from the library item, else `Kind`, else a name with an extension is an episode and a folder a season), mapped fields, images. `GET/POST CustomMetadata/Diagnostic` reads / rebuilds the library list (saved in `DataFolderPath/diagnostic.json`), **with no API call**: `notag` (episode or season without tag below a tagged season/series), `source` (unknown or disabled prefix; `tmdb`, `imdb`, `tvdb`… prefixes are ignored), `library` (provider unticked), `never` (no `custom` id). **`never` is only reliable for series and seasons**: `CustomEpisodeProvider` does not store the id on a file-backed episode (it only keeps one that is already there), so episodes are never reported as `never`. The step actions `edit-source` / `test-source` write `sessionStorage['cm-open-source'] = {prefix, test}` and go to the configuration page, which opens that source's editor at `pageshow`.
- **Click-to-fill mappings** (`config.html`, `pickTreeHtml`, `pathFor`, `setActiveMapField`): the test result starts with the answer as a tree of buttons (`#pickTree .cm-pick-leaf[data-path]`). The receiving field is the last path field focused in a mapping section (`isPathField`: text inputs of the video / season / series / episodes / person panes, except `PageParam` and `PhotoBase`). `pathFor` adapts the path: in the episodes pane everything but `#srcListItemsPath` is relative to one element (text up to the first `[0]` dropped), and a field whose id ends with `Tags` or `Genres` gets `[]` instead of `[0]`. A list of objects shows itself (clickable) and its first element under `[0]`. The tree is NOT built from `RawJson` (kept as is up to 3 MB since 2026-11-17, it used to be cut at 20 KB; the tree stays on the trimmed copy because 3 MB of buttons would be unusable) but from `SourceTestResult.PickJson`, a trimmed copy of the whole answer made by `Services/JsonPickSample` (every list cut to ONE example element, shown as `[0]`: the most complete one COMPLETED with the fields only other elements have (`Example` / `MergeMissing`, never overwriting a filled value; a nested list gets its first element completed the same way, so a nested list's `[N éléments]` stays the real count; 1000 elements scanned), i.e. the one whose `Score` counts the most filled fields (nulls, empty texts and empty lists count for nothing; first on a tie; at most 1000 elements scanned); texts to 2000 characters, depth 12, 2000 properties per object; the page shows 140 characters of a value and the whole of it in the tooltip, 2000 rows, depth 12) with `PickCounts` = real length of each cut list by path (`""` = list at the root, `data.videos`, `data.videos[0].tags`: the same path format as the page's tree). The tree is a MODEL of rows (`buildPickRows`: depth, kind `root|node|leaf`, key, path, value, `hasChildren`; 400 rows, depth 6) rendered by `renderPickTree` after `pickVisibleRows` applies, in this order: hidden paths (and what is under them; kept in `localStorage['cm-pick-hidden:<prefix>']`), folded rows (`pickCollapsed`, in memory; ignored while a filter is typed) and the filter (a row is shown when it or a descendant matches). Controls: `[data-pick-toggle=path]`, `[data-pick-hide=path]`, `#pickFilter`, `#pickCollapseAll`, `#pickExpandAll`, `#pickReveal`; the leaf buttons keep `.cm-pick-leaf[data-path]`. The page falls back to `RawJson` when `PickJson` is absent (older server, fake client of the tests).

**Second batch of UX changes (2026-11-17).**
- **Ignored missing episodes**: `DataFolderPath/missing-ignored.json` = list of `prefix-id` tags. `MissingEpisodeService.AnalyzeSeasonAsync` splits the absent episodes into `Missing` and `SeasonMissingReport.Ignored`; only `Missing` goes to `SyncVirtualEpisodesAsync`, so an ignored episode's virtual item is deleted by the usual "no longer missing" rule (and created again after "Rétablir", at the next analysis). `POST CustomMetadata/MissingEpisodes/Ignore` `{Tag, Ignored}` → `SetIgnored`, which also moves the entry in the last report and saves it, so the page and the tab counter follow without an analysis. `presentCount` in `missing.html` subtracts the ignored ones.
- **`missing.html` list view**: same markup, `.me-episodes.me-list` (CSS only), choice in `localStorage['cm-missing-view']`; the `#viewToggle` is shown at the episode level only.
- **Local element form sub-tabs** (`config.html`, `localTab`): every block of `renderLocalDetail` carries `data-lpanel="info|images|cast"` and `#localDetail[data-ltab]` hides the others in CSS, so nothing was removed from the DOM (handlers and field ids unchanged). `selectNode` resets `localTab` to `info` when the kind of element changes. A test that looks at a block must open its sub-tab first (`ltab()` in `config-local-ui.mjs`).
- **In-page confirmation** (`ask(message, options)` → Promise, `needConfirm(key, message, options, replay)`; the same block of CSS and JS is copied in `config.html`, `people.html` and `missing.html`): no `confirm()` is left in the pages. The first line of the message is the title. `needConfirm` keeps code written around a synchronous yes/no: it returns true the first time (the caller returns), then calls `replay()` (the same click or function again) once the user agreed, and on that second pass returns false. Answers are forgotten when the action went through with no other question open, so two questions in a row (people save) work. `deleteSource` still returns a boolean: false on the first pass, true on the replay. Tests answer the box with a `MutationObserver` clicking `.cmd-backdrop [data-cmd=ok|cancel]` (`window.__cmdAnswer`); overriding `window.confirm` does nothing any more.
- **Setup guide** (`#setupGuide`, `renderSetupGuide` in `config.html`): computed from the configuration, `GET CustomMetadata/Status` (`TaggedSeries` = series folders carrying a tag of a configured source, `MissingEpisodes` null = never analysed) and `checkLibraryProviders` (`libraryIssues`). Hidden when every step is done, when the status is unavailable, or after "Masquer" (`localStorage['cm-guide-hidden']`).
- **Merge of two people**: `POST CustomMetadata/People/Merge` `{KeepId, RemoveId}` (`PeopleController`): rewrites `PersonId` in the cast overlay and in every local source, THEN saves the directory (a failure in between leaves the removed entry, nothing dangling). The page refuses while it has unsaved changes, and marks the kept person as changed so that "Appliquer aux épisodes" is offered.
- **Test**: `tools/ui-test/improvements-real.mjs <url> <out_dir>` (15 checks, Playwright; seeds and restores the directory, the casts and the ignored episode). jellyfin-web upgrades the `emby-*` elements of a redrawn form a moment later: wait a little before a screenshot.

**Left-menu shortcuts.** Three pages (`Custom Metadata Provider` = config, `CustomMetadataMissingEpisodes`, `CustomMetadataPeople`; not the Diagnostic page) have `EnableInMainMenu = true` and a `DisplayName`, so jellyfin-web lists them under "Extensions" in the dashboard drawer (`MenuIcon` is ignored, the icon is a folder). **Keep the config page FIRST in `GetPages()`**: jellyfin-web 10.11 `findBestConfigurationPage` opens, as the plugin's "Paramètres" page, the first `EnableInMainMenu` page in the order the server returns (`/web/ConfigurationPages`, which keeps our array order). Flagging only another page, or putting it first, would hide the configuration page. `tools/ui-test/config-menu-real.mjs <url> <out_dir>` checks the three shortcuts, that order and that a shortcut opens its page.

**Downloads page (`downloads.html`, page `CustomMetadataDownloads`, not in the left menu).** Follow-up of the automatic video downloads (see `missing-episodes.md`). `VideoDownloadService` keeps every `DownloadJob` in memory (`_jobs`, newest 200 finished ones) with its state (`queued`, `downloading`, `converting`, `done`, `failed`, `cancelled`), detected kind, bytes done / total, error message (French, shown as is) and the file written. `Api/DownloadsController`: `GET CustomMetadata/Downloads` (`EnabledSources` = enabled sources with the option on, `Items` = `DownloadInfo`, running first, then queued, then finished newest first; `BytesPerSecond` is the average since the start, computed on the server so a clock skew cannot spoil it; for a conversion `BytesDone` is the size of the growing `.part`), `POST Downloads/Cancel|Retry` `{Key}`, `POST Downloads/Clear` (forgets the finished rows AND the failure backoff of the failed or cancelled ones). Cancelling a running job cancels its linked token (the `.part` is deleted, ffmpeg killed); a cancelled job is not queued again by the next analysis for the 6 h backoff, unless retried or cleared. The page polls every 2 s while something runs or waits (10 s otherwise), skips the redraw when the answer did not change, and stops when the hash leaves the page. The history is lost at a restart. Test: `tools/ui-test/downloads-real.mjs <url> <out_dir> <season_dir>` (Playwright; the mock API serves `b1v2.mp4` slowly on purpose).
