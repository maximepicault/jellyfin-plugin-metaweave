# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Jellyfin metadata/image provider plugin (`Jellyfin.Plugin.CustomMetadata`) that enriches media from user-configured REST APIs. Media files and folders carry an ID tag like `{PREFIX-ID}` in their names (e.g. `{mv1-123}`, `{yt-abc}`); the prefix selects which configured API "source" to query. 

## Language policy

- **Everything in the repository is written in English** so that anyone can read it: code comments (C#, HTML/CSS/JS, shell, scripts), log messages, documentation (`README.md`, `CONTRIBUTING.md`, `CHANGELOG.md`, `docs/`, `deploy/`), commit messages, pull request texts, GitHub description.
- **The plugin's user interface text is French for now** (buttons, labels, help texts and the messages the server returns to the UI). Keep it French and consistent; an English or bilingual interface is a possible later step (a translation table), not something to mix in piecemeal.
- **French is only for the conversation with the maintainer.** Never leave a French comment, doc or commit message behind. Demo data of the test bench (`tools/ui-test/data.py`) is French on purpose: it exercises the French UI.
- When a test asserts on a UI string, the string stays French inside the test, while the test's own descriptions and comments are English.

## Build

```bash
dotnet build --configuration Release      # output: bin/Release/net9.0/Jellyfin.Plugin.CustomMetadata.dll
./build.sh                                # clean + Release build
```

- The target server is **Jellyfin 10.11.6**. The project targets **net9.0** against `Jellyfin.Controller`/`Jellyfin.Model` **10.11.6** (`ExcludeAssets=runtime`). Keep the package version equal to the server version: building against a newer 10.11.x than the server can break loading.
- `Microsoft.Extensions.Http`/`Caching.Memory` must be ≥ the version Jellyfin pulls in transitively (9.0.11 for 10.11.6). Otherwise restore fails with NU1605.
- **Visual/end-to-end test bench: `tools/ui-test/ui-test.sh`.**
  - It builds the plugin and starts a Jellyfin **10.11.6** container (`cm-uitest`, http://localhost:8097, admin/admin) with a mock API (`server.py`, port 8765), tagged demo media (`gen.py`) and source prefix `dm`.
  - It then runs "Tout retraiter" and saves screenshots of the missing-episodes screen and of the config page (full page + source modal) in `~/.cache/cm-ui-test/shots`.
  - Options: `--no-build` redeploys the DLL already built (HTML pages are embedded in it, so use it only when no page changed), `--stop` stops everything.
  - If `docker ps` says permission denied (your user is no longer in the `docker` group), the container tests can't run: use `tools/ui-test/config-local-ui.mjs` (no Docker) and ask the user to fix the group.
  - `tools/ui-test/config-e2e.mjs <url> <out_dir>` is an end-to-end test of the config page against that container: edit, toggle, add, delete, global settings, and it checks what the server actually stored (including fields the form doesn't show). It restores the original config.
  - Work data lives outside the repo on purpose: the SDK-style csproj would compile the `*.cs` of a build copy placed inside it.
  - The container on port 8096 belongs to another project: don't touch it.
  - UI work follows the project skill `.claude/skills/jellyfin-ui`.
- There are no tests and no linter. A `Tests/` folder once existed but was deleted because its Moq/xUnit references didn't compile.
- To verify a change, build it and copy the DLL to `/var/lib/jellyfin/plugins/CustomMetadata/`. Then restart Jellyfin and check the log with `journalctl -u jellyfin -f`, grepping on the emoji tags below.
- The plugin config is stored as XML at `/var/lib/jellyfin/plugins/configurations/Jellyfin.Plugin.CustomMetadata.xml`.
- `Nullable` is disabled and warnings are not errors.

## Architecture

**Entry points.** `Plugin.cs` (a `BasePlugin<PluginConfiguration>` exposed as the static `Plugin.Instance`) serves `Configuration/config.html` as an **embedded resource**: after editing a page, rebuild (`ui-test.sh` without `--no-build`), otherwise the old page is redeployed.
- **`config.html` has two views.**
  - *List view*: three tabs. "Sources" shows cards (prefix, configured endpoints, an Activée switch, Modifier / Tester). "Réglages" holds the feature switches and the cache. "Configuration héritée" holds the legacy single-source fields.
  - *Editor view*: it replaces the old modal. A breadcrumb, a side navigation (Général, Endpoints, four mapping sections, Réseau, Miniatures) with "filled / total" counters, one section shown at a time, the source test docked on the right (below 1020 px of available width it moves under the form), and a sticky save bar.
  - It is all one HTML file with the same element ids as before; `readSourceFromForm`, `editSource`, `testSource`… keep their names.
- **Two save models.** Saving, toggling or deleting a source persists the whole config immediately (`persistSources()`). The global settings need "Enregistrer les réglages". The page says so.
- **`readSourceFromForm()` merges the form over the existing source.** Fields the form doesn't show (`Cast*`, `ProductionYear`, `BannerUrl`, any future field) keep their value. Before, every save rebuilt the mappings from the form alone, so those fields silently went back to their C# defaults. `ImagesArray` (video and source) is now read and written too; it was displayed but never saved.
- **An empty mapping field is ignored by the plugin**, not defaulted. A new source therefore starts with the standard paths pre-filled (`applyMappingDefaults`), and the grey placeholder is only a hint.
- **Required fields in a hidden section.** The browser can't focus them and would block the save silently. The `invalid` handler switches to the section first.
- A tag line like `{dm-…}` and the "11 / 17" counters are derived from the form, not stored.
- Jellyfin discovers the providers in `Providers/` by reflection.

- `CustomMetadataProvider` (Movie), `CustomSeriesProvider`, `CustomSeasonProvider` and `CustomEpisodeProvider` implement `IRemoteMetadataProvider<T, TInfo>`. `CustomImageProvider` implements `IRemoteImageProvider`, and `CustomExternalId` implements `IExternalId`.
- `PluginServiceRegistrator` (`IPluginServiceRegistrator`) registers **singletons** for `MetadataCacheService`, `CustomApiClient` (which owns its `JsonFieldMapper`), `SourceResolver` and `MissingEpisodeService`. Providers, `MissingEpisodesTask` and `MissingEpisodesController` get them by constructor injection. Don't `new` them up again.
- The helper classes take a non-generic `ILogger`. The registrator passes each one its own `ILogger<T>`, so `📡 [API CLIENT]`/`💾 [CACHE]` lines are logged under the `CustomApiClient`/`MetadataCacheService` category, not the calling provider's.

**Request flow (same in each provider):**
1. Extract `PREFIX-ID` with `Services/TagParser` (`Extract`, `GetOwnName`, `Strip`; the single copy of the regex `\{([\w\-]+-[\w\-]+)\}`). Run it only on the item's **own** file or folder name, from `Path.GetFileName(...)` on `info.Path`/`item.Path`. Don't run it on the full path: a season or episode would then pick up the series ID from a parent folder. Don't use `info.Name` either: it is Jellyfin's parsed title and gets truncated at things like `(2025)`, so the tag is lost.
   - **A file may carry several tags** (`Ep {dm-1} {dm-2}.mkv`) when it concatenates several API episodes: `TagParser.ExtractAll` (ordered, case-insensitive dedupe). **Episodes only**; seasons, series and movies keep the first tag.
     - The **first tag is the reference** (it is also the one stored in `ProviderIds["custom"]`). `CustomEpisodeProvider` fetches the other ids (each through its own source) and `Services/MetadataMerger` merges: tags, genres and cast are unioned without duplicates; title, overview, date, rating and number come from the first, and an empty field falls back to the next id. An unreachable extra id is skipped, an unreachable first id hands the reference role to the next.
     - `IndexNumberEnd` is set only when the API numbers are consecutive (3 and 4 → "3-4"); otherwise the provider returns the item's current `IndexNumberEnd`.
     - `CustomImageProvider` appends the other ids' images **after** the first id's, with `ProviderName` "Custom Image Provider (dm-2)", so the first stays selected by default and the rest can be picked in the image editor.
     - Missing episodes: `GetEpisodeKeys` counts every tag of a physical file as present, so `dm-2` is no longer reported and its virtual episode is deleted at the next analysis.
2. `SourceResolver.ExtractPrefixFromId` splits at the **first** `-`, so a source prefix cannot itself contain a hyphen (an old naming note wrongly said `mon-app` was valid). Then `GetSourceByPrefix` (case-insensitive, enabled sources only) → `ExtractIdWithoutPrefix`.
3. If there is no prefix, or no enabled source matches it, **return an empty result early**. Files without a matching tag are left to other providers.
4. Call `CustomApiClient.GetMetadataAsync(itemId, itemType, source, ct)`. `itemType` picks both the endpoint and the field mapping:
   - `series` → `SeriesEndpoint` + `SeriesFieldMappings`
   - `season`/`source` → `SourceEndpoint` + `SourceFieldMappings` (Jellyfin seasons represent the API's "sources")
   - everything else → `VideoEndpoint` + `VideoFieldMappings`

   The URL is built by `ResilientHttp.BuildUrl(BaseUrl, endpoint, id)`: exactly one `/` between base and endpoint whatever the user typed, and `{id}` URL-escaped.
5. **Images do not have their own endpoint.** `CustomImageProvider` → `GetImagesAsync` calls the *same* endpoint again, under its own cache key, and `JsonFieldMapper.MapToImages` extracts images using the image fields of the same `FieldMapping`. Those are direct URL fields (`PosterUrl`, `BackdropUrl`, `ThumbUrl`, `LogoUrl`, `BannerUrl`) first, then `ImagesArray`. Because each of the three mappings has its own image fields, configuring images only on the series mapping leaves seasons and episodes without images.
   - For an **episode** with no `Primary` from the API, `CustomImageProvider` also offers its `Thumb` URL as `Primary`. jellyfin-web shows `Primary` in episode lists. Without it, Jellyfin used a video frame (Screen Grabber / Embedded Image Extractor) and the API thumb was never visible.
   - **Image downloads use the source's HTTP settings.** `GetImages` remembers url → source prefix (static map). `GetImageResponse` applies `SourceHeaders` (custom headers, UA, HTTP/2) for that source even when the image is on another host (CDN), and falls back to matching the `BaseUrl` host.
   - **Portrait episode thumbnails → 16:9** (`SourceConfiguration.LandscapePortraitThumbs`, off by default). `Services/PortraitThumbConverter` centres the whole photo on a blurred, dimmed copy of itself and outputs JPEG at most 1080 px high. It applies the EXIF orientation first. It also detects a portrait picture already **pillarboxed** inside a landscape image. That needs uniform side bars (±24 per channel) of at least 8% width on each side, symmetric within 6%. It crops to the content and converts that. Every decision is logged at Info (`📐 [PORTRAIT] … is not portrait - kept as is` / `converted`). Formats SkiaSharp can't decode (AVIF, HEIC) are logged at Warning and left unchanged.
     - It runs only for episode **Primary/Thumb** images (never logos, banners or backdrops): in `GetImageResponse` for URLs remembered as such, and in `DownloadImageAsync` for missing-episode thumbnails. Series and season posters are never converted.
     - The missing-episode cache stores `ThumbLandscape`. The flag is added to the hash only when the option is on, so toggling it re-downloads those thumbnails.
     - Real episodes need "Remplacer les images existantes".
     - With the option on, a virtual episode with no cache entry ("Tout retraiter", or one created before the cache existed) has its thumbnail downloaded again instead of keeping the existing one.
     - For a video, the test button downloads up to 3 Primary/Thumb URLs and reports `PortraitThumbConverter.Describe` (real size, EXIF, side bars, readable format) in `ThumbnailChecks`. It also says when the option is unchecked.
     - It uses the **server's SkiaSharp**: `PackageReference SkiaSharp` with `ExcludeAssets runtime;native`, not shipped. The version must equal the one in the server's `jellyfin.deps.json` (3.116.1 for 10.11.6).
   - Jellyfin itself drops a 403/404 image response silently, logging only at Debug, and keeps the old image. So `GetImageResponse` logs non-2xx at Warning: `🖼️ [IMAGE DOWNLOAD] ⚠️ HTTP 403 …`.

**JSON mapping** (`JsonFieldMapper` + `JsonPathExtractor`) turns arbitrary JSON into `CustomMetadataResponse` / `ImageInfo`. Both types are defined at the bottom of `Api/CustomApiClient.cs`.
- **HTML entities** (`&amp;`, `&#39;`, `&eacute;`) in text fields (title, overview, series name, tags, genres, cast, and the episode list's title/overview) are decoded once at mapping time by `Services/HtmlText`, never for URLs. `HtmlText.Decode` is lenient on purpose: `WebUtility.HtmlDecode` alone ignores `&quot`/`&apos` without a semicolon and uppercase names (`&QUOT;`), so it adds those, and runs up to 3 passes for double-encoded text (`&amp;quot;`). a bare `quot;` (lost `&`) is also turned into `"`. `&amp`/`&lt`/`&gt` still need their `;` (`&amplifier` is not an entity). Do not decode again downstream (double decoding). The missing-episode hash includes a `html-decoded` marker, so the first analysis after the change refreshed their titles; the metadata cache (`Services/MetadataCacheService`) keeps already-cached entries undecoded until their TTL or a manual refresh.
- Paths use dot notation and are case-sensitive. A position in a list is written `[n]` (`[0].name`, `results[0].name`): `JsonPathExtractor.TryNavigate` is the single path walker (`JsonFieldMapper.TryNavigateToPath` delegates to it). A list at the root without `[0]` finds nothing; a People source says so in its error.
- Arrays of objects use `array[].field` with one `[]` level only (e.g. `tagList[].label`), or the two-field form `Tags` + `TagsItemField`.
- A comma-separated string is split into a list.
- An empty path skips the field. A missing path yields null, never an exception.
- `CustomEpisodeProvider` inserts the API's `SeriesName` as the first tag.
- **Episode number**: `FieldMapping.IndexNumber` (default `indexNumber`, editable in the video mapping) → `CustomMetadataResponse.IndexNumber`. It is applied only to file-backed episodes; virtual episodes keep the free number from `AssignIndexNumbers`.
- The episode and season providers **always return the item's current `IndexNumber`/`ParentIndexNumber`**. Otherwise "Remplacer toutes les métadonnées" (`replaceData`) copies null over them: every episode lost its number and every virtual episode was deleted by `RemoveObsoleteEpisodes`. This happened in the original code too.
- **Overview as a tag list**: `FieldMapping.OverviewListTarget` (`""`/`tags`/`genres`, in the video and series mappings).
  - `Services/OverviewListDetector` accepts hashtags only, or ≥2 short items (≤40 chars, ≤4 words, no `. ! ? :`) split by `, ; | • ·` or newlines.
  - On a match, the items are merged into the target list and the overview is cleared (`🏷️ [JSON MAPPER]` log).
  - Missing episodes apply the video mapping's option to the list overview (`DetectOverviewLists`); the option is part of their cache hash.
  - An existing overview is cleared only if it is itself a list, never a real synopsis set later by the provider.

**Jellyfin 10.11 API constraints.** `People` no longer exists on items, and `EpisodeInfo.SeriesName`/`SeasonName` were removed. Cast goes through `MetadataResult<T>.AddPerson(new PersonInfo { Type = PersonKind.X })` instead, via `Services/CastMapper.cs`. Several French docs wrongly say `PersonInfo` was removed and that casting is impossible.

**Feature flags.** Each metadata provider returns early when `EnableMetadata` is off. `CustomImageProvider` checks `EnableImages`, and `CastMapper` checks `EnableCasting`. The season name falls back as follows: API title → folder name with the `{PREFIX-ID}` tag stripped → `DefaultSourceName`. All of these are editable in `config.html`.

**Episode preview video (missing episodes only).** `EpisodeListMapping.PreviewUrl` (default `preview.url`) becomes a **local trailer**: a `Trailer` item with `Path` = URL, `ExtraType.Trailer`, `OwnerId` = the virtual episode, listed in `episode.ExtraIds`, `IsLocked`, and probed with `EnableRemoteContentProbe`. The server proxies or transcodes it on every client. This is done in `MissingEpisodeService.SyncPreviewAsync`.
- Don't use `RemoteTrailers` for this. jellyfin-web 10.11 only plays non-server URL items through a player whose `canPlayUrl` accepts them, and only the YouTube player does (`youtube.com`). Any other URL fails.
- Don't add preview trailers to real (file-backed) episodes either:
  - `BaseItem.RefreshExtras` rebuilds `ExtraIds` from disk on every refresh and deletes extras it doesn't find.
  - A `-trailer` file in a shared season folder attaches to every episode in it (`ExtraResolver.TryGetExtraTypeForOwner` same-folder rule).
- Virtual episodes are safe because `RefreshedOwnedItems` requires `IsFileProtocol`.
- `Providers/PreviewMediaSourceProvider` (`IMediaSourceProvider`, auto-discovered) also returns the preview trailer's media sources as the **virtual episode's own** sources.
  - jellyfin-web's season episode list (`listview` with `imagePlayButton`) shows a play button on every episode thumbnail, virtual ones included.
  - `MediaSourceManager.GetPlaybackMediaSources` drops the virtual episode's `Placeholder` source and keeps dynamic ones, so that button plays the preview.
  - This provider is called for every playback, so keep its early-exit check cheap.
- `CleanupLegacyRemoteTrailersAsync` strips the "Aperçu…" `RemoteTrailers` that an earlier version put on real episodes.

**Missing episodes.** Each source can set an `EpisodeListEndpoint` with an `EpisodeListMapping`. The endpoint is called per season/source, and `{id}` is the season folder's tag ID.
- `Services/MissingEpisodeService` walks every season whose tag resolves to a source with that endpoint. It compares the API list with the season's physical episodes using the key `{prefix}-{id}` (file tag, or `ProviderIds["custom"]`).
- It then creates virtual `Episode`s (`IsVirtualItem`, `ProviderIds["custom"]`, added with `season.AddChild`) and refreshes them through our providers.
- The list's `ThumbUrl` is downloaded by `CustomApiClient.DownloadImageAsync`, which applies the source's headers, HTTP/2 and timeout. It is then stored with the `IProviderManager.SaveImage(item, stream, mime, …)` overload as the episode's **Primary** image. `SaveImage(url)` would use Jellyfin's own client without the source settings, because the refresh alone did not fetch images for virtual episodes. It is also back-filled on existing virtual episodes that have no Primary image. It deletes **only** virtual episodes that carry a `custom` id and are no longer missing.
- **Every virtual episode must have an `IndexNumber` that no physical episode in the same `ParentIndexNumber` group of the series uses.**
  - On every series refresh (library scan), Jellyfin's `SeriesMetadataService.RemoveObsoleteEpisodes` deletes virtual episodes that have no number or whose number collides.
  - Without this, every scan wiped them and every analysis recreated all of them.
  - `AssignIndexNumbers` / `ComputeIndexNumbers` pick, in order: the API number if free, the number cached from a previous run if still free, then the next free number after the highest one.
- Existing virtual episodes are matched **only by their deterministic id** (`GetVirtualEpisodeId(season, key)` for wanted and cached keys) in `FindExistingVirtualEpisodes`, never by `ProviderIds`.
  - It looks among the season's virtual children, a single library query of virtual episodes grouped by `SeasonId`, and `GetItemById`.
  - A virtual episode in a managed season that matches no known key and carries no other provider's id is an orphan and gets deleted (for example, an episode whose file arrived after it dropped out of the cache).
  - Diagnostic log line: `🔎 [MISSING] Lookup …`.
- `Services/MissingEpisodeCache` keeps one JSON file per season at `DataFolderPath/missing-episodes-cache/{seasonId}.json`. Each entry stores the episode's raw API JSON, a SHA-256 of (raw JSON + `EpisodeListMapping` + `BaseUrl`), the thumbnail/preview URLs used, and whether the thumbnail download failed.
  - An existing virtual episode whose hash is unchanged is skipped entirely. Changed ones get their fields, thumbnail and preview updated.
  - "Tout retraiter" (`POST …/Analyze?full=true` → `RequestFullReprocess()`) ignores the cache once.
  - The API list itself is never cached: new episodes must show up immediately.
- `EpisodeListMapping.Duration` (default `duration`) → `RunTimeTicks` of virtual episodes, parsed by `Services/DurationParser` (`mm:ss`, `hh:mm:ss`, seconds, ISO 8601). Don't use `TimeSpan.Parse`: it reads `12:34` as hh:mm. Unparseable values log a `📃 [EPISODE LIST]` Warning.
- When `GetEpisodeListAsync` returns null (HTTP error, array path not found), the season is left untouched. Don't turn errors into empty lists: an empty list would delete every virtual episode in the season.
- The service runs from `ScheduledTasks/MissingEpisodesTask` (daily, or "Analyser maintenant"). The report is saved to `DataFolderPath/missing-episodes.json`.
- `Configuration/missing.html` is a 3-level drill-down: series cards (Jellyfin Primary image, macro recap) → that series' season/source cards → episode cards of one source (2 per row, 3 at ≥ 1800 px, 1 on mobile, thumbnail on top). A series with a single source skips level 2 (its name in the breadcrumb is then plain text). The summary is tiles on level 1 and one line of text on levels 2–3; the source header (`#context`) sits above the search field and holds "Copier les N noms" (shown episodes, one per line). Clicks and image errors are delegated on both `#context` and `#results`. Each episode shows the virtual episode's thumbnail through `MissingEpisodeEntry.EpisodeId`, plus its duration and overview. Navigation state is held in JS, not in the URL. Each episode also has a "📋 Copier le nom" button that copies `Titre {prefix-id}` (no extension, forbidden filename characters stripped; the prefix is taken from the season's `SourceItemId`). It uses `navigator.clipboard` in a secure context and falls back to `execCommand('copy')` on plain `http://IP`.
- **Plugin pages: put `<style>` inside the `data-role="page"` div.** jellyfin-web 10.11 keeps only that div, so a `<head>` style is silently dropped (verified in a 10.11.6 container: in `config.html` this left the source modal permanently displayed at the bottom of the page until it was fixed). Scope every rule under the page id: the style stays in the document while Jellyfin keeps the page instance.
- The report is served by `Api/MissingEpisodesController` (`GET/POST CustomMetadata/MissingEpisodes`, admin-only; needs `FrameworkReference Microsoft.AspNetCore.App`) and shown on `Configuration/missing.html`, which is reachable from a button at the top of `config.html`. Its shortcut (and the config page's and the Personnes page's) is in the left menu, section "Extensions" (`EnableInMainMenu` + `DisplayName` in `Plugin.GetPages()`): see below for the order rule.
- This works in multi-source mode only. The legacy global config has no list endpoint.

**Local sources (`SourceConfiguration.SourceType = "Local"`).** A source whose series, seasons and episodes are typed in the plugin instead of coming from an API, so a forced metadata refresh in Jellyfin can't wipe them, and episodes you don't have yet can be declared (they show up as missing episodes). Chosen at creation in `config.html` (the "Ajouter une source" button first offers API / Locale).
- **Data**: `Services/LocalSourceStore` keeps one JSON file per source, `DataFolderPath/local-sources/{LocalDataId}.json` (a stable random id, independent from the renamable prefix; atomic write plus a `.bak`; deleting a source renames the file to `.deleted`). Series → seasons → episodes, each node with a generated 6-character `Id` that is the `{prefix-ID}` tag to put in the folder or file name. `Normalize` keeps valid unique ids, drops duplicates and dates that aren't `yyyy-MM-dd`, and decodes HTML entities in titles, overviews, tags and genres (`HtmlText`), so pasted text (`Q&amp;A`) is stored clean and the editor and "Copier le nom" never show `&amp;`; `Load` does the same for files saved before. The served JSON is decoded once more by `JsonFieldMapper` (harmless).
- **Serving**: `ResilientHttp.GetStringAsync` returns `LocalSourceStore.Serve(...)` for a local source (no network), with the default JSON shape (`title`, `overview`, `premiereDate`, `tags`, `genres`, `poster`, `thumb`, `indexNumber`, `duration`, `preview.url`) on the default endpoints (`/series/{id}`, `/sources/{id}`, `/sources/{id}/videos`, `/videos/{id}`; base `local://local`, the host is ignored). Providers, images, missing episodes and the cache hash therefore work unchanged. `CustomApiClient` skips the metadata/image cache for local sources so edits show up immediately.
- **The endpoints and mappings of a local source are imposed**: `config.html` (`applyLocalSourceDefaults`) writes them on every save, and the API-only sections (Endpoints, mappings, Réseau, test panel) are hidden with `data-only="api"` in the editor (`#editorView[data-source-type]`).
- **Editor**: `Contenu` section = tree (series → seasons → episodes, `＋` buttons, collapsible) next to a detail form with copy buttons for the tag and a suggested name, plus a paste-a-list import per season. `Api/LocalSourceController` (`GET/PUT/DELETE CustomMetadata/Local/{dataId}`, admin-only) reads and writes the whole tree: saving a local source PUTs the content first, then persists the config. After saving, a notice offers "Analyser maintenant".
- **Test without Docker**: `tools/ui-test/config-local-ui.mjs <out_dir>` loads the real `config.html` in headless Chrome with an in-memory fake `ApiClient` (64 checks: type choice, editor sections, tree, bulk add, image upload, save order, imposed mappings, reopen, delete, API editor unchanged). It does not test the Jellyfin theme or the `emby-*` elements.
- Verified end to end in the 10.11.6 container (2026-11-13): series/season/episode metadata and images, a file with two tags (title and number range from the first, tags merged), HTML entities decoded, and two undeclared episodes created as virtual episodes with thumbnails. `tools/ui-test/config-local-real.mjs <url> <out_dir>` takes screenshots of the local editor in the real jellyfin-web (it needs a local source already in the config).
- jellyfin-web specifics met here: `<textarea is="emby-textarea">` lays its label and field side by side, so the editor uses plain styled `<textarea>`s.
- **Image upload**: each image field (poster, backdrop, logo, banner, episode thumbnail) takes a web URL or an uploaded file. `POST CustomMetadata/Local/{dataId}/Image?node={id}` (raw bytes, 8 MB max, type read from the first bytes: JPEG, PNG, WebP, GIF) stores `local-sources/{dataId}-images/{nodeId}-{random}.ext` and returns `local://img/{dataId}/{file}`, saved in the node's field; `GET …/Image/{file}` serves it for the editor preview (`?api_key=`). `CustomImageProvider.GetImageResponse` and `CustomApiClient.DownloadImageAsync` read `local://img/…` straight from disk (no network; the portrait→16:9 conversion still applies). `Save` prunes unreferenced images older than one day; deleting a source renames its image folder to `.deleted`. The editor uploads with `fetch` and `X-Emby-Token`: `ApiClient.ajax` does not send a raw file correctly (found in the real jellyfin-web, the fake-ApiClient test could not show it). Limit: Jellyfin's own image picker can't preview `local://` images (they download fine).
- Not done: ordering of series and seasons (list order), moving an episode to another season.

**People (cast directory).** Cast is its own thing, not tied to a series/season/episode source. Three source types now exist (`SourceType`): `Api`, `Local`, `People`.
- **`People` source** (`SourceConfiguration.IsPeople`): `BaseUrl` + headers + network like an API source, plus `PersonEndpoint` (default `/people/{id}`, one person per call) and `PersonMappings` (`Name`, `Photo`, `Bio`, dotted paths). `SourceResolver.GetSourceByPrefix` skips them, so a file tag can never select one. `CustomApiClient.GetPersonAsync` fetches a person (relative photo URLs completed with `BaseUrl`, entities decoded); the editor's test button has a `person` type (`SourceTestResult.Person`). An identifier is only valid for its own source (`pe-123`).
- **Directory**: `Services/PeopleStore`, `DataFolderPath/people.json` (atomic write, `.bak`). A `Person` has an internal 6-character `Id` (referenced by episode casts), `Name`, `Photo` (URL or `local://img/people-directory/…`), `Bio` and `Links` (`Prefix` + `ExternalId`, one per source; a link belongs to a single person, the first that carries it). `FindMatch` dedupes by link first, then by name (`NormalizeName`: lowercase, no accents, no punctuation). Merging is a UI decision: `POST CustomMetadata/People/Fetch` returns the API data plus `MatchPersonId`/`MatchReason` (`link`/`name`) and saves nothing; the Personnes page then offers "Ajouter l'identifiant à cette fiche". Manual edits are never overwritten by a sync: "Compléter" fills empty fields only, "Écraser avec l'API" asks first. No automatic merge on save (it would break episode cast references); the list only shows a "doublon" badge.

**Configuration (multi-source vs. legacy).** `PluginConfiguration.Sources` (a `List<SourceConfiguration>`) is the current model. Each source has its own prefix, base URL, API key, three endpoints, three `FieldMapping`s and `CustomHeaders`.
- The top-level fields (`PatternPrefix`, `ApiBaseUrl`, `VideoEndpoint`, `*FieldMappings`, …) are the legacy single-source config. When `Sources` is empty, `SourceResolver.GetDefaultSource()` builds a `SourceConfiguration` from them, and the `PluginConfiguration` constructor tries to auto-migrate them. `CustomMetadataProvider` (movies) still uses only this legacy path: it takes the ID from `ProviderIds["custom"]`, then IMDb, then the name, and never resolves a source from the prefix.
- The config is serialized with `XmlSerializer` and has no `[XmlElement]` attributes. Element names are therefore the C# names: `<Sources><SourceConfiguration><Name>…`. The hand-written XML examples in `docs/MULTI_SOURCE_GUIDE.md` (`<Source>`) don't match, and their contents would be silently ignored.
- `Dictionary` can't be XML-serialized: it caused an HTTP 500 on the config page, which is why `CustomHeader` exists as a key/value class. Keep new config types to public get/set properties with defaults.
- The only remaining legacy overload is `CustomApiClient.GetMetadataAsync(itemId, itemType, ct)` (no source), used by the movie provider. It builds the source with `SourceConfiguration.FromLegacyConfig`, as `SourceResolver.GetDefaultSource` does. Use the source-based overloads in new code. The legacy top-level config properties (including `FieldMappings`) must stay for XML compatibility.

**Provider ids: always read them case-insensitively, through `Services/CustomId`.**
- `BaseItem` creates `ProviderIds` with `OrdinalIgnoreCase`, but items re-read from the DB get a case-sensitive dictionary (`BaseItemRepository`: `Provider.ToDictionary(...)`).
- The user's DB held `Custom=…` (capital C) on virtual episodes. So `TryGetValue("custom")`, `GetProviderId("custom")` and `k == "custom"` silently failed. That broke the old lookup and orphan detection, and is why a case-sensitive SQL check showed "0 custom ids".
- Use `CustomId.Get(item.ProviderIds)` / `CustomId.IsCustomKey`. The movie provider still uses the old lookup; the user asked not to touch movies.
- Bookkeeping still does not depend on `ProviderIds` (deterministic ids, `OwnerId` for previews). `CustomEpisodeProvider` skips virtual episodes (no `Path`) without a custom id.

**Provider id key.** The plugin always stores its ID under `ProviderIds["custom"]`, and `CustomExternalId.Key` must stay `"custom"` so the id shows under "External IDs" in the metadata editor (it used to be `PatternPrefix`, which hid it). Don't make internal bookkeeping depend on ProviderIds when a structural check works: preview trailers are identified by `OwnerId` + `ExtraType.Trailer` + http(s) `Path`.

**HTTP.** Every API GET (metadata, images, episode list, source test) goes through `Api/ResilientHttp.GetStringAsync`, which never throws for HTTP/network/timeout errors and returns an `HttpFetchResult` instead. Only caller cancellation propagates.
- Each attempt has its own timeout (`SourceConfiguration.TimeoutSeconds`, default 30). `HttpClient.Timeout` is set to infinite because it would otherwise cap attempts at 100s.
- Up to `MaxRetries` retries (default 2) on timeout, network error, 408, 429 and 5xx. Backoff is 1s, 2s, 4s… (max 30s), or `Retry-After` when the API sends it. A `Retry-After` over 60s means give up. Other 4xx codes are not retried. Retries log `🔁` at Warning.
- `MaxConcurrentRequests` (default 4, 0 = unlimited) is enforced by a static semaphore keyed by `prefix|limit`, shared by every caller. The slot is released during backoff.
- These three settings are in the "⚙️ Réseau" section of the source modal in `config.html`.
- `Api/SourceTestController` (`POST CustomMetadata/TestSource`, admin-only) backs the modal's "🧪 Tester la source" button. It takes the source **as currently in the form** (unsaved), an `ItemType` (`video`/`season`/`series`/`episodelist`) and an id (`123`, `pfx-123` or `{pfx-123}`). It calls `CustomApiClient.TestSourceAsync` without cache and returns the URL, status, attempts, duration, mapped fields, images or episodes, and the raw JSON (truncated to 20 KB). Log tag: `🧪 [SOURCE TEST]`.

Headers are set in one place, `Api/SourceHeaders.Apply`. It is used by `CustomApiClient.AddHeadersToClient` (Info logs, sends `X-API-Key`) and by the image downloads in `CustomImageProvider.GetImageResponse` (Debug logs, no key). Per-source options, all in "⚙️ Réseau":
- `SendBrowserUserAgent` (default true): a fake Chrome 120 UA. When off, the UA is `Jellyfin.Plugin.CustomMetadata/1.0`.
- `SendOriginReferer` (default true): `Origin` = `BaseUrl` authority, port kept; `Referer` = `BaseUrl`. `OriginOverride`/`RefererOverride` replace those derived values when non-empty. They only apply while `SendOriginReferer` is on, and the inputs are disabled in the UI otherwise. An invalid override is skipped with a Warning.
- `UseHttp2` (default false): `DefaultRequestVersion` 2.0 with `RequestVersionOrLower`. .NET then emits the `:method`/`:scheme`/`:authority`/`:path` pseudo-headers itself. They can't be added as headers.

Then come `Accept`, `X-API-Key` (the source key, falling back to the legacy global `ApiKey`), and finally the source's `CustomHeaders`, which override the defaults. A fake browser UA (WAF bot check) or an `Origin` the backend does not allow (Spring CORS) can produce a 403 that curl doesn't get. The test button shows the headers sent, the HTTP version and the start of the error body to diagnose this. URLs containing `votre-api.com` or `example.com` are treated as unconfigured placeholders and skipped.

**Cache.** `MetadataCacheService` is a two-tier cache: `IMemoryCache` plus JSON files in `Plugin.Instance.DataFolderPath/cache`. The directory path is logged at startup as `💾 [CACHE] Cache directory:`; if `Plugin.Instance` is null, the cache falls back to a temp dir. TTL comes from `CacheTTLHours`, the whole cache is gated by `EnableCache`, and null API results are not cached.
- **Manual refreshes bypass the cache.** The series, season and episode providers pass `bypassCache: !info.IsAutomated` to `GetMetadataAsync`. On a user-initiated refresh it invalidates both `metadata:{type}:…` and `images:…:{type}` before fetching. Jellyfin runs remote image providers after metadata providers, so "Remplacer les images existantes" really picks up a changed poster.
- Automated library scans still use the cache (verified: 0 API calls).
- Without this, a changed poster or title stayed stale until the TTL expired, even with "Replace".
- Movies (legacy path) don't do this.
- An old `poster.png` sitting in a media folder that Jellyfin can't write still wins on every scan. That is Jellyfin's local-image priority, and the plugin can't override it.
- Keys are `metadata:{type}:{prefix}-{id}` and `images:{prefix}-{id}:{type}`. `CustomApiClient.GetCacheId()` re-adds the source prefix, because providers pass the ID already stripped of it.
- `MetadataCacheService.GetCacheKey()` turns keys into readable file names by splitting at the first `-` (`MV1-SEASON-SOURCE-YT.json`). The same derived key is used for the memory cache.
- Without the prefix in the key, two sources returning the same raw ID would share an entry.
- Any note that describes MD5-hashed cache file names is obsolete (the old cache notes are archived outside the repo).

**Logging conventions.** Logs are very verbose and tagged per component with an emoji prefix, e.g. `🎬 [EPISODE PROVIDER]`, `📺 [SERIES PROVIDER]`, `📁 [SEASON PROVIDER]`, `🖼️ [IMAGE PROVIDER]`/`[IMAGE FETCH]`/`[IMAGE MAPPER]`, `🔄 [JSON MAPPER]`, `📡 [API CLIENT]`, `💾 [CACHE]`, `🔍 [SOURCE RESOLVER]`, `📋 [HEADERS]`. Follow this style in new code. Debugging relies on grepping these tags.

## Git rules (agreed with the maintainer — follow them exactly)

Full human-facing version: `CONTRIBUTING.md`. What matters for the assistant:

- **Only when asked.** Commit or push only when the maintainer asks (or the request clearly includes delivering the change). Then: work on a branch, commit, push the branch, open a pull request with `gh`. Never proactively.
- **What the assistant may do:** create branches (`feat/…`, `fix/…`, `docs/…`, `refactor/…`, `ci/…`, `chore/…`, lowercase, kebab-case, English), commit, push **its own branches**, open pull requests.
- **What the assistant must NEVER do:** push to `main`, merge a pull request, create or push a tag, publish or edit a release, force-push, rewrite published history, change repository settings or branch/tag protection, use `--no-verify`. Those stay with the maintainer.
- **One pull request per topic**, squash-merged by the maintainer into `main`: the PR title becomes the commit message on `main`, so it uses the commit format below.
- **Commit messages: Conventional Commits, in English**, first line at most 72 characters: `type(scope): subject` (types: `feat fix docs refactor perf test build ci chore revert`; `!` for a breaking change). Imperative mood, no final period, body explains the *why*. One logical change per commit, no "wip".
- **Attribution.** End every commit message with the trailer for the session's model, currently `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. End every pull request description with `🤖 Generated with [Claude Code](https://claude.com/claude-code)`.
- **Changelog.** Every user-visible change adds one English line to the "Unreleased" section at the top of `CHANGELOG.md`, in the same commit. A release is its own pull request (rename "Unreleased" to `Version 0.0.N alpha (Month Year)`, open a new empty "Unreleased", align `<Version>` in the csproj); the maintainer tags after merging.
- **Before committing:** hooks active (`git config core.hooksPath .githooks`; `pre-commit` refuses bin/obj/DLL, local settings, personal paths/e-mails/tokens/private IPs, files over 1 MB, shell/JS syntax errors; `commit-msg` checks the format), build clean, relevant tests run (say which and the result), embedded HTML pages rebuilt, no screenshots or test output in the commit.
- **Personal words** (the maintainer's server name, login…) go in the untracked `.git/forbidden-words`, never in a tracked file.

## Repository, versions and releases

- **Public repository.** Keep it clean and portable: no secrets, no host names, no paths of the maintainer's machine (`/home/<user>`), nothing specific to one server. Machine-specific helpers (for example a personal deploy script) live in the PARENT directory of the repo, never inside it. `.claude/settings.local.json` is git-ignored.
